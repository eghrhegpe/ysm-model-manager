## Findings (cited - path:lines)

- `frontend/js/components/app-tree/render.js:184-191` — `renderSlice()` uses `container.innerHTML = '<div class="vs-wrap">...</div>'` which destroys and recreates the wrapper on every scroll → root cause of flicker.
- `frontend/js/components/app-tree/virtual-scroll.js:3` — `ROW_H = 28` is hard-coded; list view needs 24px row height.
- `frontend/js/components/app-tree/row-tpl.js` — grid-only templates with hover actions, icons, dates. List view needs compact variant without hover actions.
- `frontend/js/components/app-tree/tpl.js:8-14` — toolbar HTML has no view-mode toggle button.
- `go/updater/update.go:327-356` — pure functions `normalize`, `isNewer`, `splitVer` are easily unit-testable; `fetchExpectedHash` needs `httptest` mock.
- `go/dedup/dedup_test.go` — reference pattern: `t.TempDir()`, table-driven tests, Chinese error messages.

## Decisions (with rationale)

1. **List row height = 24px** (compact) — user explicitly approved. Rationale: fits more rows, consistent with compact list conventions. Reversible: one constant change.
2. **All-at-once v1.9.0 release** — user explicitly approved. Rationale: three todos are small and sequential; no need for beta churn. Reversible: N/A.
3. **Flicker fix = DOM reuse, not virtual DOM library** — keep dependency-free. Rationale: only the `.vs-wrap` element needs reuse; innerHTML of children is still acceptable for 50-100 visible rows. Reversible: easy to revert to full rebuild.
