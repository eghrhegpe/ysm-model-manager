# 3D 渲染修复总结 — 2026-06-16~17

## 核心问题

YSM 模型管理器的 3D 渲染在非 4D 皮肤模型上存在骨骼偏移、纹理错乱、旋转方向错误等问题。Go 端解析路径（`threejs.Build`）与 WASM 路径存在多处能力缺口。

## 数据流（修复后）

```
ysm.json
  ├── files.player.model[ ]  → 模型文件顺序 → texIdxMap
  ├── files.player.texture[ ] → 纹理顺序     → pngs 排序
  └── properties.default_texture → (不再使用)

ParseBedrockGeometry(model.json)
  → Cube2D {Origin, Size, Pivot, UV/FaceUV, Rotation, TexSlot, CubeTexW, CubeTexH}
  
threejs.Build(model)
  → BoneData  {localPosition, localRotation}
  → MeshData  {positions, normals, uvs, indices, texIdx}
     → 顶点: fx=ox, 相对 cubePivot
     → UV:   用 cube 自身 TexW/TexH 归一化
     → 旋转: -rx, -ry, -rz (三轴取反)
     → texIdx: 按模型文件位置截断到纹理数-1
```

## 效率提升建议

1. **重构合并策略**：`mesh merge` 按 `(boneId, texIdx, rotation)` 分组，同旋转可合并，减少 draw call
2. **纹理排序后只返回有序部分**：`textureOrder` 外的 PNG 不再返回，减少纹理数组空间
3. **`expandBoxUV` 和 `parseFaceUV` 的负尺寸验证**：构造已知 UV 的 cube 写单元测试
4. **`eulerToQuaternion` 旋转顺序对比**：需 YSMViewer C# `ThreeJsPayloadBuilder.cs` 源码确认

## 2026-06-17 补：3D 截图 + model3d.js 重构

### 3D 截图

- **当前视角**：3D 预览顶栏「📷 截图」hover 下拉菜单，6 个选项：当前视角、正面、45°、侧面、后45°、全套
- **批量**：`window.__batchRepoScreenshots(repoRoot?, outputDir?)` — 自动扫描仓库所有模型
- **多角度**：`renderMultiAngle` — 透明背景，AABB 定位，4 角度定机位截图
- **纹理**：通过 Go `AnalyzeBedrockModel` binding 获取 base64 纹理
- **清理**：每帧后 dispose geometry/material/renderer，172 模型无泄漏

### F11 全屏适配

3D overlay（`position:fixed;inset:0`）的 body flex 布局在 F11 切换时自动适配视口大小。`viewContainer` 加 `overflow:hidden` 防止 canvas 尺寸更新延迟导致内容溢出。`fullscreenchange` 事件触发 `_onResize` 强制重排。

### model3d.js 重构

将 599 行大文件拆为 3 个独立模块：

| 模块 | 职责 |
|------|------|
| `model3d.js` (~230行) | 实时渲染 + `buildSceneMesh` 导出 + `__screenshotPreview` |
| `model3d-loader.js` (~90行) | 纹理加载、spec 调用、`preloadModel` |
| `screenshot-renderer.js` (~125行) | 无头截图、多角度、批量 |

同步删除死代码 `preview-3d.js`（230 行），移除 `index.js` 中对 `preview-3d.js` 的 import。

- `batchRepoScreenshots` 并行度 1，172 个模型顺序执行，建议加并发控制
- `ExpandBoxUV` 负尺寸 UV 缺少单元测试
