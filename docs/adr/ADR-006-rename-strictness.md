# ADR-006：重命名文件名格式约束决策

- **状态**：已采纳（Accepted）
- **日期**：2026-08-03
- **决策人**：Jieling（人类首席架构师）、AI 代理
- **相关**：`frontend/js/dialogs/rename.js` / `frontend/js/dialogs/batch-rename.js` / `frontend/js/utils/display.js`

---

## 1. 背景（Context）

YSM 模型管理器的文件名格式为 `[作者]【品牌】角色名-变体(年月).ext`。
单文件重命名（`rename.js`）和批量重命名（`batch-rename.js`）共用 `parseModelName()` 解析器。

**问题**：当前重命名对话框将文件名格式**硬编码**为五个固定字段（作者 / 品牌 / 角色 / 变体 / 年月），
并以固定拼接方式重组：

```js
// rename.js:139-146
const newName =
  "[" + a + "][" + w + "】" +
  c +
  (v ? "-" + v : "") +
  (d ? " (" + d + ")" : "") +
  "." + ext;
```

这意味着：
1. **格式不可定制**：用户无法选择去掉"品牌"或"年月"字段
2. **格式不可迁移**：如果未来决定改用其他分隔符（如 `[作者][品牌]角色名`），需要改两个文件
3. **批量重命名格式锁死**：`batch-rename.js` 同样用 `parseModelName` 结果组装，没有格式切换能力

v1.0.2 引入时选择了这套格式作为默认，至今未变。

---

## 2. 决策（Decision）

**决策**：文件名格式由 `parseModelName()` 解析器定义，重命名对话框使用固定拼接格式。
不引入可配置格式模板，不做字段可选。

### 2.1 保持固定格式的理由

- **一致性**：整个仓库的文件都遵循同一套命名规范，允许用户随意组合字段会导致命名碎片化
- **可预测**：固定格式下 `parseModelName()` 的解析逻辑可以持续优化，格式变则解析器要重新适配
- **复杂度控制**：引入格式模板意味着要处理模板语法、校验、回退，对一个中型单文件对话框来说是过度设计

### 2.2 保留的约束

| 约束 | 来源 | 说明 |
|------|------|------|
| 文件名不能包含 `< > : " / \ \| ? *` | `rename.js` | 文件系统通用约束 |
| 文件名长度 ≤ 255 字符 | `rename.js` | Windows API 限制 |
| `.[字符]` 为变体分隔符 | `rename.js` | 固定格式约定 |
| `([年月])` 为日期后缀 | `rename.js` | 固定格式约定 |

---

## 3. 后果（Consequences）

### 正面
- 所有已命名的模型都遵循同一格式，仓库整齐可读
- `parseModelName()` 可以继续优化而不担心格式变化
- 批量重命名时用户只需填"统一作者/品牌"，不操心格式

### 负面
- 不符合 `[作者]【品牌】角色名` 格式的文件无法被重命名对话框正确解析和重组
- 用户想"只改角色名保留其他"时，仍然需要手动填所有字段
- 255 字符上限对极长角色名（如 VRC 模型中的长英文描述）可能不够用

### 已知限制（不修复）
- **文件名 255 字符硬限制**：Windows API 约束，无法绕过
- **固定拼接格式**：如需支持其他格式，未来可考虑将拼接逻辑抽为可配置模板
