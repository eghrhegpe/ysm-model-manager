## 1. 背景（Context）

v1.7.6 前后，前端界面存在若干可量化的体验短板，散落在多个组件中，缺乏统一的优化口径：

- 预览面板空状态仅显示 📄 + 一行文字，信息密度低、无引导；
- 预览面板详情/骨骼/3D 标签与关闭/放大等操作按钮混排，认知负荷高；
- 文件树 `.fl.selected` 选中背景过淡，几乎不可辨；
- warm（温暖木纹）主题下 `--meta-author` / `--meta-work` 与背景对比度不足，可读性差；
- 模型结构树用 ASCII 字符画（`├─` / `└─`），不够精致；
- 工具栏搜索框与筛选按钮挤在一行，操作拥挤；
- 3D 预览缺少重置视角按钮，网格线对比度低。

这些短板虽各自独立，但共同指向「视觉反馈强度 / 信息层级 / 主题一致性」三类系统性问题。原 `docs/frontend/ui-improvement-plan.md`（已于 2026-08-03 删除）以任务清单形式记录，本 ADR 将其升级为正式决策：清单是**已采纳方案的落地范围**，其背后应被长期遵守的**体验原则**才是决策真相。

---

## 2. 决策（Decision）

**决策**：采纳一套前端 UI 体验优化方案，覆盖预览面板、文件树、主题对比度、3D 预览四大面，并遵循以下统一原则（作为后续 UI 改动的评判基准）：

| 原则 | 含义 |
|------|------|
| 引导式空状态 | 空状态须提供引导文案 + 占位装饰，而非裸图标 + 单行文字 |
| 导航与操作分离 | Tab（导航）独占一行，操作按钮（关闭/放大等）置于右上角 |
| 强反馈对比 | 选中/激活等状态必须有足够对比（背景增强 + 左侧高亮条），不可"看得见但看不清" |
| 主题令牌全主题可用 | 设计令牌（含 meta 文本色）在 4 套主题下均须满足可读性，warm 主题需提高饱和度/亮度 |
| 图标化结构 | 结构树用图标 + CSS 缩进替代 ASCII 字符画 |
| 显式 3D 控制 | 3D 预览须提供显式控制（重置视角按钮 + 高对比网格线） |

具体实施范围见 §3；各项决策对应的源文件改动以「相关」与数据溯源为准。

## 4. 后果（Consequences）

### 正面
- 四类系统性体验短板（视觉反馈 / 信息层级 / 主题一致性 / 3D 控制）得到收敛；
- 提炼出 6 条可复用 UI 原则，成为后续 UI 改动的评判基准，避免反复踩坑；
- P0/P1 全部落地，主路径体验显著改善。

### 负面 / 已知遗留
- P2-8（预览面板宽度可调）、P2-9（日期着色）**尚未实施**，属计划内待办，非遗漏；
- 部分优化依赖具体 CSS 变量（`--meta-*`），warm 主题对比度修复需在各主题回归验证，存在回归风险。
