# ADR-061：3D 渲染器能力边界与后续方向

- **状态**：✅ 已采纳
- **日期**：2026-08-14
- **决策人**：Jieling（人类首席架构师）、AI 代理
- **相关**：`frontend/src/utils/3d/model3d.ts`、`frontend/src/utils/3d/spec-builder.ts`、`frontend/src/utils/animation/animation.ts`、`frontend/src/views/app-preview/model3d-loader.ts`、`ADR-049`、`ADR-052`

---

## 1. 背景（Context）

### 1.1 当前 3D 渲染器能力栈

`model3d.ts` 及其拆分子模块（ADR-040 P1）构成完整渲染管线：

| 模块 | 职责 |
|------|------|
| `spec-builder.ts` | Go `Build3DSpecFromGeometryJSON` 纯 TS 移植，生成 `Spec3D` |
| `mesh.ts` / `mesh-builder.ts` | 骨骼层级构建、网格合并（陷阱 #11：顶点预偏移） |
| `bone-raycast.ts` | 骨骼射线拾取、层级信息组装 |
| `bone-visibility.ts` | 骨骼显隐 / 组件组切换 |
| `keymap.ts` | 键位/相机速度偏好（localStorage） |
| `render-loop.ts` | rAF 主循环 + WASD/方向键移动 |
| `camera-setup.ts` / `camera-control.ts` | 相机初始化、free 模式 pointer drag |
| `debug-render.ts` | pivot/bone 可视化叠加层 |
| `cleanup-helper.ts` / `session-state.ts` | WebGL 资源释放、模块级状态复位 |

**已覆盖的功能**：静态模型渲染、骨骼拾取、debug 模式、相机交互、多组件同屏（`modelGroups`）、截图导出（`screenshotPreview`）。

**已补测试**（2026-08-14）：`screenshotPreview` 全分支 + `setSpeed`/`toggleBone`/`setBoneVisible` 直接断言，测试从 28→34 用例。

### 1.2 已存在的但尚未接入的动画引擎

`animation.ts` 提供完整的基岩动画解析与求值：

- `parseBedrockAnimationJSON` — 解析 `.animation.json`
- `evaluateKeyframes` — 线性插值（位置/旋转/缩放）
- `evaluateClip` — 单 clip 求值，支持父级变换传播（`hierarchy` 参数）

该引擎已被 `loader.ts` 和 `wasm.ts` 使用于 **2D 预览**，但 **3D 渲染器未接入**。

### 1.3 缺口清单

| 缺口 | 现状 | 优先级 |
|------|------|--------|
| 动画驱动 | animation.ts 引擎完整但 3D 未接入 | P0（用户核心需求） |
| 多模型同屏 | `spec.models` 支持多组件，但多 YSM 文件同时渲染无支持 | P2（场景需求，暂未见真实用例） |
| spec-builder 多组件 geometry | `buildMulti` 已实现多组件，但单一 geometry 文件的测试覆盖有限 | P3（Go 端已有覆盖） |

---

## 2. 决策（Decision）

### D1 · 动画驱动接入 3D 渲染器（立项方向）

**方案**：在 `renderModel3D` 的 `RenderModel3DHandle` 中新增 `playAnimation(clip: AnimationClip, boneHierarchy: BoneHierarchy)` 方法，在 `startRenderLoop` 的每帧循环中调用 `evaluateClip` 并将结果应用到 `boneGroupMap` 对应骨骼的 `position`/`quaternion`/`scale`。

**关键设计点**：
- 动画时间轴与 rAF `lastTime` 解耦：`playAnimation` 接受外部 `currentTime` 参数，由调用方控制（暂停/快进/倒放）；
- 骨骼变换优先级：动画 > 用户交互（键盘移动）> 默认姿势；
- `boneGroupMap` 的 `THREE.Group` 对象直接修改 `position`/`quaternion`/`scale`，无需重建 scene；
- 动画 clip 来自 YSM 解码（WASM 路径）或 Go binding（桌面路径），由 `model3d-loader.ts` 传入。

**不纳入本次范围**：Molang 表达式求值（标记为 `hasMolang: true` 的 clip 暂跳过，log warn）。

### D2 · 多模型同屏：暂不立项

`Spec3D.models[]` 已支持多组件（arm/armor 等），但**多 YSM 文件同时渲染**（如场景中有两个独立角色）当前无真实业务需求。若未来出现，应新建 `MultiModelScene` 管理器，而非在 `renderModel3D` 上扩展——前者是独立的场景编排问题，后者是单场景渲染问题，混在一起会破坏闭包隔离性。

**决策**：维持现状，不拓展。如有需求，以独立 ADR 立项。

### D3 · spec-builder 多组件：保持现状

`buildMulti` 已在 spec-builder.ts 中实现，`model3d-loader.ts` 的 `preloadModel` 也支持多组件（`texArrOrder` 契约）。Go 端已有完整测试覆盖。前端侧新增测试边际收益低，不立项。

## 3. 后果（Consequences）

**正面**：

- D1 立项后，3D 预览将支持基岩模型动画，用户体验从静态展示升级为动态预览；
- `animation.ts` 已有充分测试（`animation.test.ts` 20+ 用例），接入成本低；
- 现有 `renderModel3D` 闭包结构允许在 `state` 对象中新增 `animState`（当前时间、clip 引用、播放状态），不破坏现有接口；
- `BoneSelectInfo` 的 `localPos`/`worldPos` 在动画运行时仍需更新，骨骼拾取逻辑需感知动态位置。

**负面 / 注意**：

- 动画驱动引入每帧骨骼变换计算，对低端设备（Android WebView2）有性能风险——需监测 rAF 帧率，必要时降级为跳帧播放；
- `boneGroupMap` 直接修改 `THREE.Group` 属性时，`updateMatrixWorld()` 必须同步调用（`debug-render.ts` 的 `rebuildDebug` 已依赖此行为）；
- Molang 不支持意味着部分基岩模型的复杂动画（粒子/材质驱动）在 3D 预览中静默跳过，需在 UI 中标注"部分动画不可用"；
- 接入动画后，`screenshotPreview` 需在动画帧稳定后调用，否则截图可能捕获到中间帧。

**已知遗留**：

- `session-state.ts` 的 `resetRendererState` 存在引用传递 bug（传对象字面量时修改的是局部拷贝），已在本 ADR 之前的测试中发现，影响 `screenshotPreview` 无渲染器分支的可靠触发；
- `spec-builder.ts` 的 `buildMulti` 多组件路径缺乏前端单测（Go 端已有覆盖）。

## 4. 数据溯源

- **来源**：用户对话（2026-08-14）+ 代码审计（`model3d.test.ts` 测试补盲过程）；
- **决策依据**：`animation.ts` 引擎完整度（`parseBedrockAnimationJSON` + `evaluateKeyframes` + `evaluateClip` 均已测试）；`model3d.ts` 当前无动画相关代码；YSM 格式原生支持动画（`.animation.json`）；
- **相关 ADR**：ADR-049（网页版 WASM 解码路径）定义了动画 JSON 的加载入口；ADR-052（RenderSession 对象化）为动画 state 对象化提供了架构基础；
- **落地计划**：D1 动画驱动接入为独立立项，建议拆分为两轮：
  1. **第一轮**：在 `renderModel3D` 的 `state` 中新增 `animState`，接入 `evaluateClip`，rAF 循环每帧驱动骨骼变换；
  2. **第二轮**：`RenderModel3DHandle` 暴露 `playAnimation`/`pauseAnimation`/`seekTo` 接口，由 `app-preview` 组件层调用。

## 🚨 现状勘误与认知纠偏 (Post-Audit Update)

> **日期**：2026-08-xx
> **问题**：本 ADR 曾将“3D 动画驱动”标记为 P0 缺口，理由是未在 `model3d.ts` 中发现 `playAnimation` 方法。
> 
> **事实澄清**：
> - **并非未实现**：YSM (Bedrock) 动画引擎已完整落地，包含 `parseBedrockAnimationJSON`、`evaluateClip` (Catmull-Rom + Molang) 及姿态注入逻辑。
> - **架构归位**：驱动逻辑并未硬编码进 `model3d.ts` 裸渲染循环，而是由 **适配器层 (`ysm-adapter.ts`)** 托管。
>   - 入口：`createYsmAnimPlayer()` (见 `frontend/src/utils/3d/ysm-animation-player.ts`)
>   - 机制：`mdApApplyPose()` 每帧覆盖 `boneGroupMap` 矩阵。
> - **结论**：D1 (动画驱动) **实际状态：✅ 已落地**。后续开发应基于 `adapter` 接口扩展（如添加暂停 UI、Seek 条），而非重复实现底层求值器。
> 
> **修正项**：P0 优先级解除（移入已完成清单）。
