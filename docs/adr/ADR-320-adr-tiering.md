## 1. 背景（Context）

项目 2026-08-12 启动，至 2026-10-04 累计 ADR 320 份（日均约 6 份），其中「已采纳」约 292 份。抽查构成可见三类混居：

1. **架构级决策**——方向性、难逆转、值得十年后仍有人读（如 ADR-146 import 路径、ADR-196 状态层统一）；
2. **执行级拍板**——某次切片内的参数/阶段/D1-D7 细项决策（如「D2 λ 锚定域宽」「§2.4 交付物形态」），价值随实施完成而衰减为历史注脚；
3. **勘误/复决**——对前一份 ADR 某一小节的修正（被取代链仅 7 份显式标注）。

ADR-319 落地批的 D1/D2/D3/D4 独立成四份编号 ADR 即典型样本：单份信息密度趋近于 commit message，而全局检索时编号串联噪声大（routes-quick 中 `ADR-127, ADR-132, ADR-253` 式列举）。`check-adr-health.ts` 治的是格式病（状态机/登记同步/技术债提取），不治信号稀释病。

## 2. 决策（Decision）

**ADR 分两级目录，模板与门禁跟随分级**（方向拍板，存量不回溯迁移，增量执行）：

1. **`docs/adr/architecture/`（架构决策）**——沿用 `ADR-NNN` 主编号与现有全量模板；准入判据：方向性 + 难逆转 + 跨域影响面。现有 320 份中预估仅少数（1/10 量级）够格，按「新 ADR 必答」甄别，存量不搬。
2. **`docs/adr/decisions/（执行决策日志）`**——轻量模板（背景一句 / 决策三行 / 关联主 ADR），子编号挂靠主 ADR（如 `ADR-319-d2`），不进 nav 顶层、sidebar 折叠；价值定位 = 可 grep 的决策档案，不是必读文献。
3. **登记表分两节**：`adr/index.md` 按 architecture / decisions 分节维护，`check-adr-health` 状态机只对 architecture 强制全字段（decisions 豁免「决策人」等重字段）。
4. **门禁跟随**：`new-adr.ts` 增加级别参数（默认 decisions，architecture 需显式声明理由一句）；`adr-check` / `check-adr-drift` / `gen-vitepress-sidebar` 适配双目录。
5. **被取代链补课**：取代关系仍走状态字段 `已取代（被 [ADR-NNN] 取代）`，decisions 级修正优先降级挂靠主 ADR 而非新占主编号。

**落选方案**：① 单目录 + frontmatter `type` 标签分级——检索噪音仍在目录遍历与编号空间里，不解决稀释；② 冻结新 ADR——决策流照常，不现实。

## 3. 后果（Consequences）

- **正面**：主编号恢复稀缺性（年均两位数而非三位数）；新人/AI 检索先命中 architecture 层，执行细节按需下钻；ADR-319 式批量细项决策不再稀释主编号。
- **负面 / 成本**：门禁适配工作量（5 个脚本 + 登记表结构）；「该进哪级」的判断成本转移到立 ADR 时（用默认 decisions + 显式升级的保守策略对冲）。
- **已知遗留**：存量 320 份保持原位不迁移（历史编号是稳定锚点，搬迁收益低于断链风险）；`已取代` 仅 7 份的补课不做强制，跟随 `check-adr-health` 技术债报告增量消化。
