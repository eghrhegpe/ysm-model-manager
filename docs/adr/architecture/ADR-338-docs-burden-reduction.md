# ADR-338：文档体系减负：分级连带 + 知识卡域合并 + ADR 增量门槛（62% 连带率的治理）

- **状态**：🔄 部分采纳（试点刀已落地，其余待拍板分批推进）
- **日期**：2026-10-13
- **决策人**：Jieling（人类首席架构师）、AI 代理
- **准入理由**：近三周 62% 的代码提交连带 docs/登记表（均 2.1 文件/commit），知识卡 208 张已有 10 张持续漂移——连带成本接近功能开发本身，边际负担正在惩罚高频改动；方向涉及全仓工作流约定与三套生成物，不可单点回退

## 1. 背景（Context）

### 1.1 量化账本（2026-10-13 实测）

| 指标 | 数值 | 来源 |
|------|------|------|
| 含产品代码的提交连带 docs/登记表 | **62%**（691 提交中 430） | `git log --since 2026-09-20` 逐提交 diff-tree 统计 |
| 每提交均摊文档触量 | 2.1 文件（不含门禁修复工时） | 同上 |
| 知识卡规模 | 208 张（另 ADR 356 篇、check-* 脚本 49 个、契约测试 123 个） | 文件系统盘点 |
| 持续漂移 | 10 张卡 WARN/ERROR（机器闸全天候盯着仍追不平） | `check-knowledge-drift` 多日观测 |

漂移数字是核心证据：208 张卡 + 全自动门禁，仍有 10 张在漂——**「写回知识卡」纪律已超过人（和 AI）能维持的负载**，体系在靠闸门惩罚使用者而非帮助使用者。

### 1.2 成本结构的定性诊断（2026-10-13 锐评修复批的实证）

当天 800 行产品代码的修复批，配套消耗了同等量级工时在：知识卡 4 张更新 + ADR 2 篇 + 4 套登记表（bus 发射端 / a11y 基线 / testid 契约 / 路由表）核对修复 + pitfalls 案例 + 门禁往返。其中**零价值连带**占大头：改两行 CSS 与改数据流走同一套全流程；「作者菜单改 click 展开」这类单点裁定也值得一篇 ADR。

### 1.3 不该动的（显式豁免）

- **机器闸本身**（49 check + 123 契约测试）：真防线，实测各拦下过真遗漏（a11y 基线闸 / bus 发射端闸在当天各拦一次）
- **实证修正型记录**（pitfalls、ADR 的「落地实录」节）：如 composedPath retargeting 这类跨会话必踩的坑，必须留
- **routes-quick / index 生成物**：它们是检索基础设施，问题是输入碎（卡多），不是机制错

## 2. 决策（Decision）

三分刀，按风险递增排序，**每刀独立可回退**：

### 2.1 第一刀：分级连带（低风险，纯工作流约定）

代码改动分诊两档，走不同连带强度：

| 档 | 判定 | 连带要求 |
|----|------|----------|
| **行为改动** | 改数据流/判定/绑定签名/存储键 | 现行全流程（知识卡 affected 检查 + 回归锁 + 相关登记表） |
| **表层改动** | 纯样式值、纯文案（i18n value）、测试自身、注释 | 免知识卡检查；`--files` 照旧；登记表仅在其真被触碰时核 |

落地形态：`check-knowledge-drift --affected` 增加白名单（样式文件/纯测试路径不触发卡检查）——**不是弱化闸，是收窄触发面**。

### 2.2 第二刀：知识卡域合并（中风险，本次试点已落）

粒度裁定：**一张卡 = 一条可独立讲述的链/域**，不是「一个文件一张卡」。判据：两卡正文互引 ≥2 处 + 消费场景重叠 → 合并候选。

- **试点已落**（2026-10-13）：`utils-mc-format` + `utils-icon` + `utils-display` 三卡 → 合并为 `utils-display.md`「文件名展示与着色链」（解析→§着色→图标是一条流水线，正文互引成环）。旧卡 `git mv docs/archive/` + 文首活指针，入链 6 处改指新卡，`gen-knowledge-index` / `gen-routes-quick` 重生成，**drift 检查回到基线（0 ERROR / 3 WARN 无新增），doctor --docs 23/23 绿**
- **推广已落**（2026-10-13）：`utils-extensions` + `utils-resource-types` → 合并为 `utils-resource-types`「资源类型与扩展名派生层」（互引 1↔1 + 同源 `schema.ts` 派生层 + 消费重叠）。原卡 `git mv docs/archive/` + 活指针，入链 2 处改指，`gen-knowledge-index` / `gen-routes-quick` 重生成，**drift 回基线（0 ERROR / 3 WARN 无新增）、doctor --docs 23/23 绿**
- **推广中验证否决两组**（判据量化截图：互引计数）：`utils-array`+`utils-fmt`+`utils-misc` 互引 0↔0（数组移动/格式化/调试三个独立域，无互引无重叠——拟合并是「都小所以合」的伪判据）；`utils-errors` 并入 `utils-dom` 互引 0↔0（错误翻译 vs DOM 工具，不同域）。**结论：合并判据必须是可量化的互引 + 消费重叠，不是「文件小/同目录」这类形态相似**（pitfalls #27 同构判断原则的应用）
- **推广净收益**：除合并本身外，顺带消除了 2 个既有覆盖盲区（`move-dnd.ts` / `batch-all-settled.ts` 补登进 app-tree 卡——合并前就在盲区）；`dnd-shared` 的 broad_claim 旗标随 extensions 主卡并入目录覆盖后条件不再满足，按门禁处方移除（5.15 全重复认领消除，恰是「一条注册表链一张卡」减少了重复认领面的证明）
- **踩坑记录**：合并卡 source_files 若从目录级改精确文件，会引入两处连带——①`utils/resource/` 目录下其他文件（importable.ts 等）失去覆盖 → 盲区上升；②精确条目与 redline-enforcement-grade 等审计卡的 source_files 撞车。**处理**：保留目录级 `frontend/src/utils/resource/` + 补回原卡的两条精确文件（`types-re-export.ts` / `repo-rtype.ts`，在 `utils/` 根非目录下），目录符号 <100 阈值不膨胀。教训：**合并卡 source_files 形态（目录级 vs 精确）是独立决策点，不是跟正文走**
- 顺带修的两条既有 WARN：`utils-dom` 目录级 source_files 收窄（107 个派生符号的膨胀根因）；`community-feature.md` 硬编码行号清理

### 2.3 第三刀：ADR 增量门槛（要拍板，未落）

ADR 回到「架构史」本位：**只有跨域 / 难逆转 / 改变公共契约的决策才立 ADR**；单点执行裁定（如「菜单 hover 展开 → click 展开」）降格为知识卡内「裁定记录」一行 + 提交信息，不再占主编号。预估可砍掉 decisions/ 目录约半数增量。**此刀影响 `new-adr.ts` 工作流与 AGENTS.md 约定，待用户拍板后另批执行**。

## 3. 后果（Consequences）

### 3.1 正面

- 连带率可度量地下降（试点组：3 卡 → 1 卡，后续推广预计知识卡总量 208 → ~190，检索路由词密度提升）
- 漂移面收窄：合并后同一事实只有一处维护点（试点前三卡各自写「§ 着色消费方」，合并后单点）
- 分级连带直接削掉表层改动的仪式成本

### 3.2 负面 / 已知风险

- **合并卡变长**（试点卡 ~130 行 vs 原 78+58+58）：AI 检索命中后要读更多无关段——以 `quick_intents` 关键词对位缓解（合并卡 5 条意图覆盖原 3 卡全部路由词），实测命中率待两周观察
- **archive 卡的活指针靠自觉**：无人阻止新引用直接指 archive——`check-doc-drift` 已有对 archive 目录的 srcExclude 语义，若回流成患可升级为硬闸
- 分级连带的「表层改动」判定需要判例积累，初期可能有误判（宽放 → 漏卡；严放 → 白跑闸）

### 3.3 度量与止损

- **两周后复测**：连带率（同款 git 统计）、drift 计数、`routes-quick` 命中抽检 10 例
- 试点组若有「找不到卡」的检索失败 → 回滚合并（`git mv` 回来 + 删活指针，零代码耦合所以零成本）
