# ADR-338-d3：提交密度公约——一个工作单元一个提交

- **状态**：📝 提议中（Proposed）
- **日期**：2026-10-24
- **决策人**：Jieling（人类首席架构师）、AI 代理
- **关联主 ADR**：ADR-338
- **相关**：`docs/knowledge/commit-granularity.md`、ADR-338-d1（提交信息减负闸）、`backup/pre-squash-20261024`（2026-10-24 压缩先例分支）

---

## 背景（一句）

AI 并行会话按「一锐评条目一 fix 提交 + 一 docs 回填提交 + 一 test 补锁提交」的粒度累积，发版窗口密度达同期同类仓（dsh 插件）12 倍（v1.15.0 后 3 周 1114 个提交、其中纯文档 21%、中位数每提交仅 4 文件），且处置证据依赖 commit 哈希锚，密度与碎锚互相强化。

## 决策（三行）

1. 提交单元 = 工作单元（一轮锐评处置 / 一个 feature / 一次重构收口）：fix+test+docs 回填合体为一个提交，生成物由 pre-commit 搭车；不逐条目碎提交，docs 回填不单独成提交。
2. 锐评/处置的可追溯锚以**条目号**（如 锐评P2⑤）为主、commit 号为辅；压缩/合并场景在合并提交消息体里列出原哈希清单保映射。
3. 2026-10-24 先例：未推 85 提交按工作单元压缩为 7 个（`git commit-tree` 按边界树重建，终树与原 HEAD 逐字节一致；原历史备份于 `backup/pre-squash-20261024`）。**已推送历史不重写**。

## 后果（一句）

发版窗口提交量预期降 4-5 倍回到同类仓量级；代价是单提交 subject 承载多主题（由消息体条目清单补偿，commit-msg 减负闸采集期提示不阻断）；回退 = 拒绝本 ADR（提案态，删公约行与卡即可），已压缩历史不回滚（备份分支保留）。
