# ADR-343-d1：搜索语义收敛C1：关键词匹配单口径（名/相对路径/拼音三路）+ 拼音表单源派生

- **状态**：✅ 已采纳（Adopted）
- **日期**：2026-10-15
- **决策人**：Jieling（人类首席架构师）、AI 代理
- **关联主 ADR**：ADR-343

---

## 背景（一句）

模型仓库功能锐评 P1-1：关键词搜索存在**两个匹配面**（树内联搜索 = 前端 `relPath.includes`；高级筛选 = Go `SearchModels` 对 `Name` + **绝对** `Path` 的 `strings.Contains`），且双双无拼音/首字母——中文模型名（主体用户）搜「xh」找不到「小红」，搜「2024」先撞上作者文件夹墙。

## 决策（三行）

① **单口径匹配语义**：`hit = (name 或 相对路径) 小写子串命中 || 拉丁字母关键词在 name 的拼音全拼/首字母中命中`；关键词命中一律按**仓库根相对路径**匹配（`SearchModels` 现绝对路径匹配废止，文件夹名仍可读但子串面收窄为相对路径，消「2024 撞文件夹墙」的一半——剩余噪音由 CJK 关键词的精确子串语义保证不误伤）。
② **拼音表单源**：Go 侧依赖 `github.com/mozillazg/go-pinyin`（默认读音集，多音字取默认音），CLI 命令 `pinyin-table` 生成 `frontend/src/utils/search/pinyin-table.ts`（字符→拼音表，生成物入 git）——Go/TS 两侧判据**同源同表**，防跨语言手抄漂移（仓内「模板与实现靠金样例对账」既有范式）。
③ **双面同判据 + 金样例对账**：Go 侧 `go/pinyin|MatchKeyword(name, relPath, kw)` 单点实现；TS 侧 `utils/search/match.ts` 用同一张表实现同语义；`tests/fixtures/search-golden.json` 金样例（含 CJK/拼音/首字母/相对路径/大小写/空值）由 Go 单测与 `tests/test_search_parity.ts` 契约测试双读对账（browser-adapter B1 家族同款防线）。

## 后果（一句）

`SearchModels` 关键词面行为变更（绝对→相对路径 + 拼音三路），Go/web/CLI 三面经金样例锁死同判据；web 侧 `searchWebModels`（Worker 数值统计）关键词面同切 `utils/search/match.ts`（纯函数，Worker/主线程同模块）。回退：删表 + 还原 `strings.Contains` 绝对路径匹配（`git revert` 单提交可逆）；拼音表生成物可整体删除（TS 侧退化为无拼音面）。
