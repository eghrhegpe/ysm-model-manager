# 导入队列与命名表单

## 它能做什么

把文件拖入或通过文件选择器加入**导入队列**，程序自动判定每个文件是否需要进入**命名表单**（`.ysm` 需命名、`.zip/.7z` 需检测内容），并串行处理避免并发冲突。

## 打开方式

- **拖拽**：把文件/文件夹拖入主窗口（「放开以导入模型」浮层）
- **文件选择器**：点击导入按钮选择文件或文件夹（支持文件夹递归）

## 操作步骤

### 1. 加入队列

- 拖入或选择的文件进入导入队列（PendingImport）
- 文件夹导入时保留相对路径（`_relPath`），还原目录结构

### 2. 判定是否进命名表单

| 文件类型 | 处理 |
|---------|------|
| `.ysm` / `ysm.json` | 始终进入命名表单 |
| `.zip` / `.7z` | 调 Go 端 `DetectZipType` 检测内容：是 YSM → 进表单；否则按资源类型导入 |
| 其它已注册扩展名（.pmx/.vrca/.nbt 等） | 直接导入，不进表单 |

### 3. 并发保护

- 队列带锁（`DnDLock`）：一次只处理一个导入流程，避免重复拖拽/重复导入竞态
- 批量导入上限：单次最多 50 个文件，单文件 100MB

### 4. 完成

- 导入完成状态经事件总线广播（`import:pending-changed`）
- 可到 [模型仓库](./repository.md) 查看新文件

## 常见问题

**Q：zip 被判定为非 YSM？**
A：`DetectZipType` 按内容判断；仅当压缩包内部包含 `minecraft:geometry` 格式 JSON 才识别为 YSM。

**Q：命名表单可以跳过吗？**
A：`.ysm` 需要命名（模型展示名）；其它类型直接导入无需命名。
