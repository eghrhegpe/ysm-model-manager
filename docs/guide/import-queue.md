# 导入队列与命名表单

## 它能做什么

「📥 导入」tab 是批量导入的工作台：文件加入队列后逐个处理，`.ysm` 等模型文件弹出命名表单规范命名，其它类型直接入库；队列带锁，避免重复拖拽造成冲突。

## 打开方式

- 「📚 模型仓库」→「📥 导入」tab（拖入 YSM 文件时程序会自动切到这里）
- 拖拽区点击选择文件，`Ctrl`+点击选择文件夹（递归读取并保留相对目录结构）

## 操作步骤

### 1. 命名表单

`.ysm` / `ysm.json` / 判定为 YSM 的压缩包会进入内联命名表单（提示「导入仓库前，先重命名一下吧：」）：

| 字段 | 说明 |
|------|------|
| 作者 | 必填（空则按原文件名处理） |
| 作品品牌 | 空则记为「未知」 |
| 角色名 | 必填 |
| 变体 | 可选 |
| 年月 | 勾选「当天」时自动填当前年月 |

- 表单会先从原文件名自动解析出作者（`[作者]`）、作品（`【作品】`/`《作品》`）与年月作为预填
- 勾选「读取作者」可从模型文件头提取作者信息自动填充
- 下方实时预览最终文件名，格式为 `[作者]【作品】角色-变体 (日期).扩展名`
- 仓库已有同名文件时显示 ⚠️ 冲突提示
- 点「📥 导入」后还会弹出「✂️ 重命名模型」确认框（可最后微调），确认后入库；「✕」取消

### 2. 命名规则

- 作者、角色名不能为空
- 文件名不能包含 `< > : " / \ | ? *` 等字符
- 完整文件名不超过 255 字符

### 3. 队列处理与并发保护

- 文件按加入顺序串行处理，计数显示「N 个已导入 · M 个待处理」
- 队列带锁（DnDLock）：处理期间的重复拖拽会被忽略，避免竞态；拿不到锁的任务保留在待处理队列，不会静默丢失
- 成功提示「✅ 已导入: 文件名」，失败提示「❌ 导入失败: 原因」，并自动刷新文件树

### 4. 覆盖确认

导入遇到同名文件时弹出「文件已存在」确认框：选择「覆盖」走覆盖导入（提示「✅ 已覆盖」），或取消保留原文件。

## 常见问题

**Q：zip 被判定为非 YSM？**
A：内容检测按压缩包条目名判断——`pack.mcmeta` 归资源包、`shaders/` 归光影包、`ysm.json` 或 `models/` 归 YSM，都不匹配时默认按 YSM 进表单。

**Q：命名表单可以跳过吗？**
A：`.ysm` 需要命名（这是仓库命名规范的入口）；其它类型直接导入，无需命名。表单里的字段留空时会回退为原文件名/「未知」。

**Q：队列卡住了？**
A：锁会在文件读取完成后约 1 秒自动释放；若长时间无响应，切出再切回「📥 导入」tab 或重启程序。
