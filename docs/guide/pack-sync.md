# 整合包同步

## 它能做什么

管理 Minecraft 整合包中的 YSM 模型与资源：自动检测已安装的游戏实例（支持标准 `.minecraft/versions` 与 PrismLauncher 布局），逐个整合包查看「仓库 ↔ 整合包」的同步状态，一键推送/拉取，启用禁用状态双向同步。

## 打开方式

主界面左侧导航栏 →「🎮 整合包管理」。左侧为整合包列表，点击某个整合包后右侧显示它的同步管理面板。

## 操作步骤

### 1. 整合包检测与卡片

- 程序根据游戏根目录自动枚举整合包：标准布局读 `versions/` 下各版本，PrismLauncher 读 `instances/` 下各实例
- YSM 模组检测：扫描整合包 `mods/` 目录，打开候选 JAR 的 `mods.toml` / `neoforge.mods.toml` 匹配 `yes_steve_model`
- 每张卡片显示：整合包名、📦 计数徽章（绿 = 已同步、红 = 待推送、橙 = 整合包多出）；未装 YSM 模组的整合包挂灰色「🚫 无YSM」徽章并排序靠后
- 底栏显示「完全同步 x/y」统计；「🎮 未设置」按钮可一键自动检测游戏目录
- 右键整合包卡片：📂 打开文件夹 / 📄 复制模型清单 / 🗑️ 清空此整合包的模型（走回收站，可恢复）

### 2. 同步状态（六个筛选标签）

右侧面板顶部按状态筛选：

| 状态 | 含义 | 操作 |
|------|------|------|
| 📊 全部 | 不过滤 | — |
| ✅ 已同步 | 仓库有且已安装 | — |
| ⬇️ 待推送 | 仓库有但整合包没有 | 点「推送」 |
| ⛔ 已禁用 | 已同步但仓库侧被禁用（`.ban`） | 仓库启用即可 |
| 📤 可拉取 | 整合包有但仓库没有 | 点「拉取」 |
| 🔗 旧仓库遗留 | 整合包多出的旧硬链接文件 | 点「拉取到此仓库」 |

### 3. 推送与拉取

- **单文件**：待推送行的「推送」→ 安装到整合包的 `config/yes_steve_model/custom`（YSM 类型）；可拉取行的「拉取」→ 复制到仓库
- **批量**：侧栏顶部勾选整合包 →「⬆️ 推送所选 ▾」/「⬇️ 拉取所选 ▾」，菜单可选类型（📦 全部类型 / 💎 YSM / 🎭 MMD / 🥽 VRC / 🎨 资源包 / ☀️ 光影包 / ⚙️ 蓝图 / 📐 投影）
- 批量推送完成提示「📥 …导入 N 成功, M 失败」，失败原因可在 [诊断与去重](./diagnostics.md) 的操作日志查看

### 4. 启用/禁用双向同步

- 仓库里切换模型开关后，文件监听会自动把所有整合包中的对应文件重命名（加/去 `.ban`），约 1 秒内生效
- 也可手动触发：同步面板「🔄 同步状态」按钮对全部整合包做一次状态对齐（完成提示「✅ 同步完成：禁用 X 项，启用 Y 项」或「状态已一致，无需更改」）

## 常见问题

**Q：整合包列表为空？**
A：确认游戏根目录配置正确，目录下有 `versions`（或 PrismLauncher 的 `instances`）文件夹（见 [首次配置](./first-setup.md)）。

**Q：推送时报「不同分区，不支持硬链接」？**
A：链接模式为硬链接但仓库与游戏目录跨分区。到「设置 → 基础设置」切换 📋 复制模式后重试（不会自动降级）。

**Q：复制模式下启用/禁用不同步？**
A：复制模式的整合包文件与仓库互相独立，需要重新推送；硬链接模式是即时联动的。

**Q：「🗑️ 清空此整合包的模型」会删什么？**
A：只清空「仓库中已存在同名」的文件（走回收站可恢复），整合包独有的文件保留不动。
