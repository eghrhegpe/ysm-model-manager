# 前端设计令牌债务 — 剩余 157 条决策记录

> 快照：自 463 条基线逐步收敛至 135 条降为已知债务现场。本文件是**人工逐簇判定**的记录，
> 非生成物、非机器索引。每次大门禁刷新基线后，此处 `count` 会高于实时值（本文件是判据存档）。
>
> 判定框架：**「闸报违规」≠「必须修」**——先看该写法在仓内是否有正当机制与主流先例，
> 再决定「归位」「留存量（豁免）」或「立项建专属档」。**数值近 ≠ 角色对**：令牌按角色命名，
> 一个值对应多角色时，任何单一令牌都「部分正确、部分误导」，宁可不归位。

## 判定口径（本次会话逐步固化）

1. **归位**：语义明确 + 位移 ≤1px（或用户拍板接受 ±2px）+ 方向匹配 → 改走既有令牌。
2. **留存量（豁免）**：归按钮档会语义错位 / 位移 >2px / 方向残缺（横向强 0 或轴向不一）→ 保留硬编码，记录理由。
3. **立项候选**：同值多角色但形成高频语义簇（如输入框 `4px 6px`）→ 若要清白需建专属档（`--field-padding`），权衡令牌面膨胀后决定。

## 立项候选（若未来想要「清白」）

1. **`--field-padding` 输入框/控件专属档**（值 `4px 6px`/`5px 8px`），可清约 10+ 处输入框/下拉。代价：新令牌 + 输入框角色语义。**D4 防膨胀口径反对为散点建**——需统计覆盖率后再定。
2. **`--fs-2xl` 空态大图标档**（32-36px），可清 `.empty .big`(36px)。代价：把 `--fs-*` 最大档从 25px 扩到 32-36px，影响全局放大语义。

## 回顾（收纳是否合理 — 批判性复盘）

### 成果账本
一次会话把硬编码 padding/字号 从 **463 → 157**（−306，−66%），其中：
- **机械建档**（早期 + 本会话）：`--btn-padding-{sm,md,std,xs,tool-lg,filter-lg}`、`--sp-vh-{btn,hdr,card,pane,block,perf}`、`--pad-v-{1,2}` 等组合/纯垂直档，`--fix` 批量清 200+ 处
- **人工逐条归位**（本会话末）：`3px 0`/`0 5px`/`1px 4px`/诊断域/真按钮/标签按钮，清 ~20 处
- **留存量**：`4px 6px` 多语义簇 / 方向残缺 / 大位移 / 真特有色 / 品牌字号 / `→` 排版符号

### ✅ 合理的（实证支撑）
- **新建档语义纯净、消费一致**：`--pad-v-1/2`（17+8 处全为垂直呼吸行）、`--sp-vh-perf`（8 处全为 perf 诊断图表）、`--sp-vh-hdr/card`（10/12 处全为栏/卡片行）——**无一外溢到异角色**，是真有角色的档，非「硬编码搬进 var」。
- **收尾判断正确**：剩余 157 以多语义簇/方向残缺/大位移/真特有色为主，归位会引入语义错位或令牌面膨胀，留存量是合理终点。

### ⚠️ 可质疑的（如实记录）
1. **档位数量膨胀**：一次会话新增 7 个组合/纯垂直档。横向 **2px（perf）/ 0（pad-v）/ 10（std）** 等**非标准横向**档，稀释了「令牌 = 标准值」的定义——这是 D4 防膨胀的制度张力，需警惕「为了降债务而制造更多令牌」。
2. **位移成本隐性化**：全程标榜「值等价零位移」为主，但**实际接受大量 ±1~2px**（`--pad-v-2` 3→2、`btn-sm` 4→3、`btn-std` 3→4、`sp-vh-perf` 6→8）。这些**未做视觉回归**就提交，纯 CSS 值变化，风险需量化——虽多为 1-2px 微调，但累计影响面未核实。
3. **早期 `--fix` 机械替换埋下的语义错配**（**重要发现**）：`a09e41ae6`（ADR-295 组合档落地，基线 377→311）那波 `--fix` 用「`4px 8px`→全部归 `--btn-padding-md`」无差别机械映射，把**容器/表格/网格**（`.cr-grid`/`.gh-grid`/`.perf-matrix`/`.list`/`.ins-model-list`）也归进了**按钮档**——这正是「数值近 ≠ 角色对」的典型反例，且**至今残留**（`btn-padding-md` 有 32 处消费，其中约 10 处是容器/表格类非按钮语义）。**这不是本轮失误，但暴露了「机械 `--fix` 高效却粗糙」的代价**：后续若追求语义纯度，这批需从按钮档拆出到专属容器/表格档（`--field-padding` 立项候选正是为此）。

### 方法论沉淀
- **机械 `--fix` 是双刃剑**：一次清 67 处很爽，但对 `4px 8px` 这类「按钮/容器/表格三义值」，无差别套 `--btn-padding-md` 是**语义债的转移而非消除**。**本会话人工逐条能区分角色、只归该归的**，正是对早期机械粗糙的纠偏——但只修了部分，残余仍留。
- **「值等价 + 语义纯净」才是健康收纳**；「减计数」本身不是目标，避免为数字好看而制造语义错位或令牌面膨胀。

## 结论

剩余 157 条已被**逐簇评估**，绝大多数为「多语义簇 / 方向残缺 / 大位移 / 真特有色」——**归位会引入语义错位或令牌面膨胀，收益不抵代价**。判定：**保留为已知债务**，闸继续报但归位不优先；后续仅在遇到「该簇被触碰」时顺手收敛（触碰即收），或专门立项建专属档。这不是治理失败，而是**债务治理的合理终点**——把「规范漂移」与「行为缺陷」分开，前者可通过闸持续监控、不必强清。
