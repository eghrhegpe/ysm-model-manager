# 国际化 i18n 模块

## 概览

`i18n` 模块是 YSM 前端的唯一翻译层，基于 ADR-045 设计。`t.ts` 提供纯函数式翻译（按 key 查表），`locale.ts` 管理语言状态、持久化与异步加载。支持简体中文（基准）、英语、日语三种语言，语言偏好持久化到 `localStorage`，切换时通过 `bus` 广播 `lang:changed` 事件驱动全量重渲染。

## 核心职责

- **翻译查表**: `t(key, params?)`（严格 LocaleKey 入口）/ `tOf(key, params?)`（string 入口，动态 key）— 从当前语言包取字符串，支持 `{key}` 插值；**缺失键多级回退**：current → `FALLBACK_LANG`（en）→ 裸 key（经 `warnMissingKey` 单次 `console.warn`）；`getBundle` 对空包/未加载内部 rescue 至非空 `BASE_LANG`（zh-CN），两常量与 `SUPPORTED_LANGS` 同处单一事实源；插值走 split/join 字面量替换（对 `$&`/`$1` 特殊序列免疫）+ **残留占位符守卫**：替换后文本仍含 `{ident}` → 按残留签名告警一次（堵「模板有 `{n}` 漏传参」裸占位符上屏，ADR-207 D3）
- **动态 key 兜底**: `tOf` 承载数据驱动 key（`labelKey` 数据字段，如 3D 菜单 cap-controls、右键菜单 BATCH_TPL 模板表）+ 缺失键多级回退；原 `tr`/`trDynamic` 双入口生产调用点归零，随 ADR-210 D3 根除（`LocaleKey | (string & {})` 洗白 union 同步退役）
- **语言状态管理**: `_currentLang` 持久化到 `localStorage.uiLang`，启动时优先读持久值，其次经宿主通道检测系统语言（`detectFromLangs` 纯策略，宿主实现读 `navigator.languages`），兜底 `BASE_LANG`（zh-CN）
- **语言包异步加载**: `loadLocale(lang)` — 经 `LocaleHost` 注入通道从 `public/locales/{lang}.json` fetch（宿主实现 `utils/dom/locale-host.ts`，装配层 `setLocaleHost` 接线，ADR-210 D1 引擎无关）；幂等缓存 + 在途 Promise 去重（`pendingLoads`，并发同语言只发一次 fetch，失败后在途表清空可重试）；失败不缓存空对象（删除键允许重试）；未注入 host → 告警一次跳过（fail-open）
- **初始化**: `initI18n()` — 读取持久化/系统语言 → 经宿主同步 `<html lang>`（zh-CN → zh-Hans 映射策略在 core，宿主只设属性）→ 并行预载三包（current + FALLBACK_LANG + BASE_LANG，回退链各层冷启动可达）→ 成功后 emit `lang:changed`（补发一次让首帧渲染的空 bundle 组件重渲染）
- **并发安全**: `setLang()` 用 `_langReqGen` 代际计数，快请求后到可覆盖旧写入，防竞态；`initI18n` 仅做初始写一次，await 恢复后对账 `code === _currentLang` 才补发事件（被 setLang 覆盖则不替写者补发）
- **缺失 key 告警节流**: `warnMissingKey(key)`（每 key 一次；可变 Set 保持模块内私有，ADR-207 D3 收编），切语言时清空节流表

## 对外 API / 入口

- `t(key: LocaleKey, params?)` — 严格字面量 key 翻译（拼错编译期报错；动态 string key 用 `tOf`）
- `tOf(key: string, params?)` — string 版 t（动态 key；缺失键多级回退 current → FALLBACK_LANG(en) → 裸 key + 单次告警；取包时 getBundle 内部 rescue 至 BASE_LANG）
- `getLang()` — 读取当前语言代码（`LangCode`）
- `setLang(code)` — 切换语言（异步，加载语言包后触发 `lang:changed`）
- `initI18n()` — 启动时调用，读取持久化/系统语言，并行预载 current + FALLBACK_LANG + BASE_LANG 三包（回退链冷启动可达；语言包获取失败不悬挂启动链）（装配层先 `setLocaleHost` 再调用）
- `setLocaleHost(h)` — 注入宿主实现（DOM 副作用通道，`utils/dom/locale-host.ts` 提供 `makeLocaleHost`，ADR-210 D1）
- `detectFromLangs(langs)` — 系统语言候选 → 支持语言纯策略（宿主读取 navigator，策略在 core）
- `getBundle(lang?)` — 获取翻译包（已加载时直接读缓存；空包/未加载 rescue 至非空 `BASE_LANG`，再无则空对象）
- `FALLBACK_LANG` — 缺失键兜底语言单一事实源（en，与 SUPPORTED_LANGS 同处，成员守卫见 locales-consistency 测试）
- `BASE_LANG` — 基准语言单一事实源（zh-CN：LocaleKey 类型源 + getBundle 空包 rescue 目标，与 FALLBACK_LANG 同处，成员守卫同上）
- `SUPPORTED_LANGS` — 支持的语言常量列表（含 code / label / key）
- `warnMissingKey(key)` — 缺失 key 单次告警（locale 模块内节流）

## 与其他子系统关系

- `bus`: `setLang` / `initI18n` 完成后 emit `lang:changed`，订阅者（app-nav / app-content / 各组件）据此重渲染
- `utils/base/primitives/storage.ts` (`safeGet`/`safeSet`): 用于 `localStorage.uiLang` 读写，避免隐私模式裸调抛错中断启动链
- `scripts/generate-locale-json.ts`: 从 TS 源文件生成运行时 JSON，放在 `public/locales/`
- `zh-CN.ts` 是基准语言包，`en.ts` / `ja.ts` 须与之一一对应（脚本可校验完整性）
- **新增翻译 key 同步规则**：新增 key 须三语言同时添加，由 `i18n-check` 脚本校验完整性

## 不变量

- 基准语言为 `BASE_LANG`（zh-CN，命名常量与 FALLBACK_LANG 同处），未知语言回落 `BASE_LANG`，再 fallback 到空对象
- 语言状态写统一门控：切换走 `setLang`（代际门）；`initI18n` 仅初始写一次，await 恢复后对账 `code === _currentLang` 才补发事件，不可旁路
- 语言包加载失败时删除缓存键（非缓存空对象），允许后续重试
- 隐私模式下 `localStorage` 读写经 `safeGet`/`safeSet` 包装，静默降级不中断流程
- **键名迁移 = 同步改调用点 + 删旧键**（ADR-124 §2.3 实施调整）：改名键时同步改全部调用点 + 测试断言 + 三语言包，旧键从语言包直接删除；**无 `legacy-key-map.ts` 兼容表**。禁止「保留旧键等兼容回退」——旧键残留是 i18n_accuracy.md 记录的「改旧键以为生效实则无效」陷阱根源
- 模板含 `{ident}` 占位符的调用必须传 params（残留守卫按签名告警一次，裸占位符不上屏）
