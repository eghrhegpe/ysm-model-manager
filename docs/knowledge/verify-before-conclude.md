# 可复现结论纪律（结论必附验证证据）

## 概览

本卡约束**怎么下结论**——不针对某个子系统，而是针对「判断本身」的纪律。适用于审计报告、知识卡正文、ADR、提交说明，也适用于对话中给用户的答复。

**一句话**：凡是「X 已清 / X 是误报 / X 慢 / X 有多少处」这类**关于现状的断言**，都必须能贴出一条**别人可复跑的命令**；贴不出的，就只能说「我读了代码，看起来是…」，**不得当作事实继续往下推**。

## 为什么需要它（事故驱动，2026-10-08 实录）

同一天内，主模型对同一批代码连续下错四类结论，**每一次都不是门禁的错，恰恰是门禁/实测把结论推翻的**：

| 说过的结论 | 实际 | 错法 |
|---|---|---|
| `drift-scan` 报的 `INLINE_BAN_STRIP` 是误报 | **真违规**——该行在 heredoc 内且其后有 `go run genindex.go`，是真被执行的 Go | 读了规则输出，**没读被命中代码的上下文** |
| 静态工具段成本 24.4s | 真实 push **63.0s**（契约测试 32.6s 占一半） | **手测清单条目之和**冒充运行时 |
| push 走 `allMode` 分支无条件全量 | push **不传 `--all`**（`allMode = args.all`），落域裁剪分支 | **看结构不追数据流** |
| redlines「账粗于实 63 vs ≈22，可收账」 | live **66**，账本 63 反而**偏低** | **凭印象报数**，没跑门禁 |

四次的共同点：**把「读到的结构/注释/印象」当成了「已确认的事实」**。

### 另一类：注释与知识卡里的旧结论被当定理

`ci-tuning` 曾记「覆盖率并进 race 一次编译——实测反而变慢，已回退」。据此**差点放弃**一个能省 80.2s 的方案。复测发现：**被打回的是「合并 + `-p 1`」**，变慢主因是 `-p 1` 串行化所有包，**不是合并本身**。→ 原结论被**过度归纳**，丢掉了适用参数（`-p 1`）。

**教训**：**记错题必须连参数一起记**，否则后人复测时对不上，会走回头路。

## 纪律条文

### 1. 结论必附「命令 + 原始输出 + 日期」

- 写「实测 N 秒 / N 条 / N 处」时，**同段内**给出复跑命令与日期。
- 反例（现存，待补）：台账卡记「17 处事实锚点型已修正（提交 56d257823）」——**无复现命令**，后人无法核。
- 允许的降级表述：`（读码判断，未实跑：<文件:行> 显示…）` —— 明确标注**未验证**，且**不得**据此继续推高阶结论。

### 2. 注释 / 知识卡 / ADR 里的旧结论 ≠ 证据

- 读到「已回退 / 实测变慢 / 不适用」这类断言，**先复测再采信**；尤其当它是**放弃某个方向**的理由时（代价最大）。
- 复测不一致时：**不是删掉旧结论，而是补上参数与日期**，写明「当时测的是什么方案」。
- 仓库既有防线（呼应本条）：ADR「背景/Context」被明确定义为**决策时的历史快照 ≠ 当前状态**。

### 3. 静态结构 ≠ 运行时路径

- 「某分支无条件全量」这类判断，必须追到**入参赋值处**（如 `allMode = args.all` 与调用方是否传该 flag），不能只看分支体里调用了什么。
- 判断「谁在跑什么」的唯一可信方式：**跑一次并抓它的输出**（`--dry-run` 常只出计划，不执行——别拿它当运行证据）。

### 4. 计数与耗时从工具取，不从清单累加

- 运行时成本：跑真实入口（如 `pre-push-gate` 走真实 refs），**不要**手测清单里每个脚本再相加——会漏 spawn、漏环境瞬态、漏未列出的项。
- 计数：用门禁的 `--json` 输出，不凭印象（`≈22` 与 `66` 的差距就是印象的代价）。

### 5. 改动验证的口径要匹配改动域

- 改 `scripts/` 下 `.ts`：**必须** `npx tsc --noEmit -p scripts/tsconfig.json`。
  - 实测事故：加护栏时漏了 `worst ? … : "?"` 空值守卫，`biome` 与运行时冒烟**都不报**，只有 `scripts tsc`（TS18048）能抓。
- 改工作流 YAML：跑 `test_workflow_contract_order` / `check-workflow-refs`，并**自测判定脚本**（喂构造输入）。
- 改门禁的依赖图：同步知识卡的 `invariant_anchors`（否则 `check-knowledge-drift` 报 ERROR——**它今天正是这么抓住改 `needs:` 却漏改锚的**）。

### 6. 子代理计数一律降级处理

- 仓内既有纪律（见 `tech-debt-ledger`）：凡子代理报的债，**先亲自 grep + 跑门禁**再决定动手。
- 实录：子代理报「71 处死锚 / 27 卡」，而**全仓无任何脚本产出「死锚」这一度量**——系其自造启发式产物，不可入结论。

## 不变量

- 任何「现状断言」必须可追溯到一条命令；追溯不到的，表述里必须自标「未验证」。
- 复测与旧结论冲突时，**补参数**而非删旧结论。
- 门禁报红 ≠ 门禁有问题——**先假定它是对的**，回源码核验后再判断误报（顺序反了会浪费一整轮）。

## 与其他子系统关系

- **门禁层**：本纪律的多数「红线」已被机器兜底——`check-knowledge-drift`（锚失效/计数引用）、`check-adr-health`（ADR 状态与取代链）、`check-doc-drift`（文档链）、`scripts tsc`（脚本类型）。**本卡不重复造闸**，只补「机器看不见、但人常犯」的那半（印象报数、结构当运行时、旧结论当定理）。
- **台账卡** `tech-debt-ledger`：记录**有哪些债**；本卡记录**怎么判断债的状态**。两者互补：台账的每条结论都该满足本卡第 1 条。
- **AGENTS.md**「查证优先」节：本卡是它的操作化补充——那边说「不确定就查」，这边给出**查到什么程度算数**。
