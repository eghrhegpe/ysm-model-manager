# 第 02 区域 · 第 2 章 · 错误的名字

> 区域归属：`02-模型仓库`（`go/installer` `go/sync` `go/updater`）
> 时间线标签：vol-4
> 对应真实事件/代码改动：`3016c71`（fix(installer): 链接错误 errno 分类——errnoIs 平台分支 + linkErr/symlinkErr errno 优先 + 文本兜底）、`0d16e3a`（fix(sync): isFileLocked errno 优先）

---

## 一 · 被叫错名字的旅人

那是一个跨分区硬链接失败的深夜。

用户把模型仓库放在 D 盘，把游戏放在 C 盘，点了"安装"。`installer` 捏着那个失败的 `os.Link` 错误，翻来覆去看了两遍，然后给它贴了个标签：

**"权限不足，请以管理员身份运行。"**

用户照做了。以管理员身份又试了一次。错误还是那个错误——因为那个错误根本与权限无关。它叫 `EXDEV`，意思是"跨设备，我不认识你的另一个分区"。

`installer` 后来承认，它认错的依据是一段英文文本里的一个词。它有一套老式的辨认法：把错误变成小写字符串，然后用 `contains` 一个个比对——`"cross-device"`、`"access"`、`"permission"`。

「这不是认人，」外科医生后来评价，「这是听口音。一个外国人用流利的中文说'我饿'，你听不出来他是谁，但你会先带他去吃饭。」

被叫错名字的不止 `EXDEV` 一个。`isFileLocked` 也在用同样办法辨认"文件被占用"——靠 `"sharing"`、`"access"`、`"used by another process"` 三个词。Windows 上文件被 Minecraft 锁住时，它会从错误文本里找"sharing"；偶尔找得到，偶尔找不到，取决于那天错误的心情。

而最危险的是：**认错了名字，用户就按错的提示去操作**。以为缺权限，其实缺的是一个分区；以为文件被占用，其实那是另一个错误。

## 二 · 查户口本

「错误不该靠听口音辨认，」外科医生说，「错误有户口本。」

`installer` 第一次听说"户口本"这个概念。它跟着外科医生走到一堵墙前，墙上钉着两排编号：

```
Unix:   EXDEV = 18        EACCES = 13        EPERM = 1
Win32:  ERROR_NOT_SAME_DEVICE = 17   ERROR_ACCESS_DENIED = 5
        ERROR_PRIVILEGE_NOT_HELD = 1314   ERROR_SHARING_VIOLATION = 32
```

「你看，」外科医生指着两排数字，「同一件事，两个世界叫两个号。18 在 Unix 是'跨设备'，17 在 Windows 才是。如果你只记一个号，在另一个世界就会认错人。」

`installer` 盯着那面墙，忽然觉得背后发凉——它以前不查户口本，靠的是一句**"听起来像"**。

于是它学会了一件事：辨认错误之前，先看自己在哪个世界。

```go
// errnoIs：先确认世界（平台），再查户口（errno）
func errnoIs(err error, unix, win int) bool {
    if runtime.GOOS == "windows" {
        return errors.Is(err, syscall.Errno(win))
    }
    return errors.Is(err, syscall.Errno(unix))
}
```

户口本查不到的时候，才轮得到老办法出场——英文文本的 `contains` 降级为最后的兜底，像一个老翻译，只在签证官都不认识来客时，才凭口音勉强猜一下。

「注意一个细节，」外科医生说，「Windows 的 32 号在 Unix 是 `EPIPE`，而管道破裂这种事，`os.Link` 永远不会干；Unix 的 18 号在 Windows 是 `ERROR_NO_MORE_FILES`，跟链接更沾不上边。两边的号**互不串门**——所以查户口永远安全。」

「查错户口会怎样？」`installer` 问。

「17 在 Unix 是 `EEXIST`，」外科医生说，「你会在目标文件其实已存在的时候，告诉用户'分区不同'。那比权限提示还离谱。」

## 三 · 两个世界的号

`linkErr` 和 `symlinkErr` 都换了新规矩。`isFileLocked` 也换了。

硬链接失败，先问世界：是 Windows，查 17 号——跨分区，建议切复制模式；查 5 号——权限，建议管理员。是 Unix，查 18 号——跨分区；查 13 号或 1 号——权限。

符号链接失败，Windows 查 1314 号——那是最著名的"创建符号链接需要特权"，也就是用户没开开发者模式时，系统给的那记响亮的耳光；Unix 查 1 号 `EPERM`。

「1314，」`installer` 念着这个数字，「在 Unix 里根本不存在这个号——所以它永远不会在 Unix 世界被误认。」

「对，」外科医生说，「这就是户口本比口音强的地方：**每个号都有自己明确的世界，不会越界认亲。」**

测试也补上了：跨设备 errno 该提示"不同分区"、权限 errno 该提示"权限不足"、未知错误回退通用文案——每一类都有人证（测试用例）盯着。

## 尾声

`installer` 后来再遇到那个跨分区的 `EXDEV`，它不再说"请以管理员身份运行"了。

它查了户口本，知道来客叫 `EXDEV`，家住在 Unix 的 18 号，然后它如实告诉用户：

**仓库与游戏目录在不同分区，不支持硬链接——请在设置中切换为复制模式。**

用户照做了，问题消失了。

它想：名字是会骗人的——同一个错误，在两个世界里有两个名字；而它以前认人，靠的是名字的"口音"，不是名字的"户籍"。口音会骗人，户籍不会。因为户籍是错的字，是有编号的、查得到的、有测试盯着的。

它把户口本收好。那本子上每一条编号后面，都站着一个曾经被叫错名字的旅人。

**缝**：把错误分类从"听起来像"升级为"查得到"，靠的是相信编号比口音诚实——但编号的诚实只维持到下一个新平台出现为止。等到第三个世界（比如 WASM 里的什么新错误模型）降临那天，这本户口本又要重新编页。

---

**教训**：错误的本名在户口本里，不在口音里。
