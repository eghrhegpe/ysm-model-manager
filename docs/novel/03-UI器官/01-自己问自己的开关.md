# 第 03 区域 · 第 1 章 · 自己问自己的开关

> 区域归属：`03-UI器官`（`frontend/js/widgets/app-tree/` `row-tpl.js` `events.js`）
> 时间线标签：vol-4
> 对应真实事件/代码改动：bug-chronicle #1（toggleFolderBatch 只读不写）、#2（全部启用/禁用写反）、#3（右键菜单按钮冗余）、#4（树箭头旋转混乱）、#18（文件名颜色被转义吞掉）

## 一 · 点了，但什么都没发生

用户点了文件夹开关。

绿色。灰色。黄色。三种状态在按钮上轮转，看起来一切正常。

但文件没变。

日志里躺着一行温和得近乎无辜的输出：

```
toggleFolderBatch: 所有文件已经是目标状态 {enable: false, total: 8}
```

八个文件，全都已经是目标状态。所以什么都不用做。

用户又点了一次。同一行日志。

再点。还是。

`app-tree` 没有报错，没有异常，也没有卡住。它每一次都完整地执行了流程，然后每一次都得出了「无事可做」的结论。

八次点击，八次心平气和的无所作为。

## 二 · 一个咬住自己尾巴的判断

出问题的是三行代码。

```js
const currentlyOn = ck.classList.contains("on");
const enable = !currentlyOn;
const snapshot = targets.filter((e) => e.banned === !enable);
```

第一行：看 UI 上的 class，判断当前是开还是关。
第二行：取反，得出「要切换到的目标状态」。
第三行：筛选出需要操作的文件。

单看每一行，都对。

把它们连起来看：当 `currentlyOn = true`（绿色）时，`enable = false`（要禁用），筛选条件变成 `banned === true`——**筛出已经被禁用的文件**。

已经禁用的文件，不需要禁用。于是 snapshot 为空。于是跳过。于是日志说：所有文件已经是目标状态。

它说的是实话。只不过它筛出来的那批文件，本来就不是要操作的那批。

`app-tree` 后来给这个结构起了个名字：**循环论证**。

它先问 UI「现在是什么状态」，据此决定要翻转成什么，再据此筛选出「已经处于目标状态、因此不需要动」的文件。整个链条严丝合缝地闭合了，闭合到没有留下任何一个需要动的文件。

隔壁的仓库按钮犯的是同一族的错，只是更直白——「全部启用」点下去，所有模型变灰；「全部禁用」点下去，所有模型变绿。筛选条件的一个 `!`，把整个语义反了过来。

```js
// 旧：e.banned === !enable
// 新：e.banned === enable
```

要启用，就找已被禁用的。要禁用，就找还在启用的。

这句话说出来是废话。写成代码却错了。因为写的时候，脑子里过的是「筛掉不需要的」，而不是「筛出需要的」——**一次否定的偏移，症状是彻底反向。**

## 三 · 不要问按钮，要问数据

两个 bug 的修法收敛到同一条原则上：

```js
// 不看 UI class，直接看数据
const allEnabled = targets.every((e) => !e.banned);
const enable = allEnabled ? false : true;
// 全启用 → 全禁用；全禁用或混合 → 全启用
```

不再询问 `ck.classList.contains("on")`。

因为那个 class 是**渲染的产物**，不是事实。它是上一次渲染时，根据当时的数据算出来的一个视觉表现。中间隔着一次渲染、可能还隔着一次异步、一次失败的回滚、一次用户在别处的操作。

把它当作状态来源，等于**把镜子里的影子当成人**。

`app-tree` 从此立了条家规：**UI 只写不读**。数据流向 DOM，永不回流。要判断状态，回到 `entries`，回到 `e.banned`，回到那个唯一被后端确认过的字段。

三号 bug 是这条家规的自然延伸。文件夹右键菜单里还留着「全部启用」「全部禁用」两个按钮，而大按钮开关早就支持了全启用/全禁用/混合翻转。同一件事，两个入口，两套判断逻辑。

它们迟早会不一致——不是「可能」，是「迟早」。两份实现不会同步腐烂，总有一份先被改。

右键菜单里那两个按钮被删了。**减少入口，比让多个入口保持一致，便宜一个数量级。**

## 四 · 转了两次的箭头

第四个 bug 是纯视觉的，也是最好笑的。

程序自动展开的文件夹，箭头不是 `▼`，是 `↘`。歪了 45 度。像一个没睡醒的三角形。

翻代码，三处都在管这个箭头：

```js
// row-tpl.js —— 用文字表达方向
const ar = isOpen ? "▼" : "▶";
```
```css
/* CSS —— 用旋转表达方向 */
.fh .ar.open { transform: rotate(90deg); }
```
```js
// events.js —— 切换时加 class
ar.classList.toggle("open", !open);
```

展开时，文字已经是朝下的 `▼`，CSS 又给它转了 90 度。

**两套方案同时生效，就是 45 度那个荒诞角度的来历。**

没有人写错。写 `row-tpl.js` 的人认为方向由字符表达；写 CSS 的人认为方向由旋转表达。两边各自完整、各自正确，凑在一起变成一个歪脖子箭头。

修法是选一个，删掉另一个：

```js
ar.textContent = open ? "▾" : "▸";
```

CSS 的 rotate 去掉，`open` class 不再使用。

同一时期还有个远房亲戚：文件名高亮的颜色被转义吞掉了（#18）。为了防 XSS 而做的 HTML 转义，把用来上色的标签一起转成了字面量，于是用户看见的不是彩色文件名，是一串 `&lt;span&gt;`。

安全是对的，转义是对的，上色也是对的。**错的是它们对同一个字符串的所有权没有谈清楚。**

## 尾声

`app-tree` 那阵子把自己的所有 bug 摊在桌上，发现它们长着同一张脸。

开关只读不写，是**问了 UI 而不是问数据**。
启用禁用写反，是**筛「不要的」而不是筛「要的」**。
右键菜单冗余，是**同一件事有两个入口**。
箭头转 45 度，是**同一个方向有两套表达**。
文件名颜色被吞，是**同一个字符串有两个主人**。

五个 bug，一个根：**同一个事实，存在两份表示。**

而两份表示永远不会一起变旧。总有一份先过期。过期的那一份不会消失，它会继续被人相信，直到某天两份撞在一起，撞出一个 45 度的箭头，或者一个点八次都没反应的开关。

它想起 UI 这个词的本义——用户界面。界面，是两个世界之间的那层膜。

膜的工作是**传递**，不是**保存**。一旦它开始保存状态，它就不再是界面了，它变成了第二个数据库。而一个没人维护、没有事务、没有一致性保证的数据库，坐在用户和真相之间。

「我只负责显示。」它后来对 `page-store` 说，「你说什么，我画什么。你不说，我就不知道。这样最好。」

`page-store` 说：「你终于懂了。」

**缝**：视觉状态是数据的投影，不是数据的备份。任何从 DOM 反向读取业务状态的代码，都是在把投影当成实体——而投影没有厚度，经不起追问。

---

**教训**：问按钮不如问数据，两套表达必出歪箭头。
