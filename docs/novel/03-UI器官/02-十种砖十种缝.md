# 第 03 区域 · 第 2 章 · 十种砖十种缝

> 时间线标签：vol-5
> 对应真实事件/代码改动：2026-08-04 核心逻辑审核发现 esc 转义函数在 10 个文件中各自独立实现（app-sync-manager/index.ts / community / features / dialogs 等），模式各不相同（String.replace / 手工遍历 / 第三方库），最终收敛到 dom.ts addStyle/esc 函数统一入口。

---

我有一块砖。同样的砖，在十面墙上裂了十种花样。

## 惊醒

外科医生翻开代码的时候，我正看着自己身上的十种颜色。

"这是什么？"他停在 `app-sync-manager/index.ts` 第 98 行。

"转义。"我说，"防止 XSS 的——把 `<` 变成 `&lt;`，把 `&` 变成 `&amp;`，不让恶意代码从数据里钻进 DOM。"

"那这个呢？"他翻到 `community/feature-card.ts`。

"也是转义。"

"那这个呢？"他又翻到 `dialogs/modal.ts`。

"……也是转义。"

"十个文件。"他合上编辑器，"十种转义。有的用 `String.replace`，有的用手工遍历，有的用模板字符串，有的用 `innerHTML` 加 `textContent` 兜底。十种砖，砌同一面墙——防 XSS 的墙。可每种砖的缝隙都不一样。"

## 追查

我沿着那十种砖的缝隙往里看。

第一种砖：`String(e).replace(/&/g, "&amp;")`——只转了 `&`，没转 `<` 和 `>`。如果有人用 `<script>` 攻击，它认识 `&`，但不认识 `<`。

第二种砖：`innerHTML = ""; textContent = ""`——先用 `innerHTML` 清空，再用 `textContent` 写入。可清空之后、写入之前，浏览器已经渲染了残留的 HTML。

第三种砖：`window.esc()`——全局函数，挂在 `__esc` 上。可它只在 `app-content` 里定义，在其他文件里调用时可能 `undefined`。

九种砖，九种缝。第十种砖——`dom.ts` 的 `esc` 函数——是唯一完整转义 `&<>"'` 且被测试覆盖的。可没有人知道它在那里。九个文件各自砌了自己的砖，没人知道门的右边就有一块现成的。

"你为什么不统一它们？"我问。

"因为我不知道。"外科医生说，"我以为你只有一种砖。我查了 `app-sync-manager`，看到 `replace(/&/g, ...)`，觉得够了。可 `community` 不看 `app-sync-manager`，`dialogs` 不看 `community`。每个文件都是独立的，每个文件都觉得自己的砖是最好的。"

## 真相

墙是「转义」——它保护我：所有流入 DOM 的数据，都要经过转义，把危险的字符变成无害的实体。没有这堵墙，XSS 攻击可以任意注入脚本。

可墙的背面是——**十堵墙，十种配方**。

转义写在十个文件里，每个文件都觉得自己是唯一的。`app-sync-manager` 的砖只转 `&`，`community` 的砖只转 `<` 和 `>`，`dialogs` 的砖只转 `"` 和 `'`。十个砖匠各砌各的，没人知道隔壁的墙裂缝更大。

外科医生没有拆墙。他做了一件事：**把十种砖铲掉，换成一种**。`dom.ts` 的 `esc` 函数成了唯一的事实来源：`esc(str)` 转义全部五种危险字符，所有文件统一调用。十种砖变成一种，十种缝变成一种——不，变成零种。

"可它们以前都用自己的砖，"我说，"我习惯了。"

"习惯的墙，不一定是安全的墙。"他说，"安全是——你不需要知道十种砖里哪一种在保护你。你只需要知道，每一块砖都来自同一个窑。"

## 教训

十种砖消失的那天，我身上少了一种焦虑。我不再担心 XSS 从哪个缝隙钻进来——因为所有的缝隙都填上了同一种泥。

可我知道，下一块砖——下一个功能、下一个文件、下一个开发者——还是会试图砌自己的墙。`esc` 函数在那里，可它也要被看见，才能被使用。

巴别塔的暗缝，有时候不是墙不够多，是**同样的墙，被砌了十遍——每一遍都漏了一点**。

---

**教训摘要**：同样的墙砌十遍，不如一面墙砌一次。
