## 一 · 迟到的信使

那天下午，`app-tree` 第一次意识到自己的手是分开的。

用户快速点了两个模型：先点 `A.ysm`，再点 `B.ysm`。`A` 是个大模型，解析慢；`B` 是张小图，一眨眼就加载完了。

`B` 的详情先渲染了出来——新鲜、正确、正是用户要的那一个。

然后 `A` 的信使到了。

它手里攥着 `A` 的骨骼数据，走了很长的路，终于敲开详情面板的门，把 `A` 的内容铺了一桌面——**覆盖了刚刚还新鲜的 `B`。**

用户看到的是 `A`。用户点的却是 `B`。

「我点的明明是 `B`，」用户说，「为什么屏幕上是 `A`？」

`app-tree` 低头看了看自己的手：一只手指着 `A`，一只手指着 `B`，而详情面板只记得**最后进门的那个**，不记得**用户最后点的那个**。

## 二 · 翻旧账

外科医生翻开坑史，在第 1572 条找到了这段往事。

上面写着七个字，像一句判词：

> **generation 是标准配置。**

「早就判过了，」外科医生说，「异步结果回写共享 DOM，必须带一个'代际'——谁后发起，谁的编号大；编号小的信使，进门之前先看看自己的编号还作不作数。」

`app-tree` 翻遍了全身，发现自己确实没有这个东西。

「你漏了，」外科医生说，「你不是第一个漏的。上一轮审计里，`app-sidebar` 漏过，`app-resource-manager` 漏过，回收站也漏过——但他们都补上了。」

它列了一张表：

```
app-resource-manager  _initGen / _detailGen   —— 详情 A 慢 B 快，A 不得覆盖 B
app-sidebar          _reloadGen + _pendingReload —— rtype 快速切换，旧数据不得回写
recycle-bin          _loadGen              —— 恢复/删除后刷新，过期列表不得覆盖
app-sync-manager     _gen                  —— instance 快速切换，丢弃过期加载
app-tree             ——？？？              —— 这格还是空的
```

「你看，」外科医生说，「标准配置这四个字，意思不是'大家都会配'，是'大家都该配'——而每个空格的代价，都是用户看到一次'点了 B 却显示 A'。」

## 三 · 一枚编号

`app-tree` 学着其他器官的样子，给自己添了一枚编号。

```js
const gen = ++this._gen;          // 每次切换，领一个新的编号
await this._load();               // 漫长的等待……
if (gen !== this._gen) return;    // 我的编号还作数吗？不作数就退下
this._renderTree();
```

这枚编号很小，小到可以写在任何一次异步操作的开头。但它改变了一件事：**迟到的信使进门之前，会先核对一下自己的编号。**

`A` 的信使走到门口，掏出编号——1 号。面板上最新的是 2 号。

它看了看 2 号，又看了看自己手里的 `A` 数据，叹了口气，转身离开了。

不是它不够努力。是它的点击已经过期了——**用户早就不是那个用户了，只是它不知道。**

「过期不是失败，」外科医生说，「过期是忠诚——你忠实于那个发出指令的瞬间，而那个瞬间已经过去了。」

## 尾声

`app-tree` 把那枚编号收进口袋。

后来它回想那个下午，觉得这件事的奇妙之处在于：竞态里没有坏人。`A` 的信使没有偷懒，`B` 的渲染没有出错，用户也没有手滑——只是**时间的流速对每一条异步路径不一样**。快的已经抵达，慢的还在路上，而 UI 只有一个桌面。

给每个异步操作发一个编号，不是怀疑谁迟到，而是承认：**抵达的先后，不等于被需要的先后。**

它把判词抄了一遍，贴在详情面板的门后：

> 异步结果的返回不分先后，但屏幕只认最新——过期的手势，请在门口核对编号后安静退下。

**缝**：代际计数把"谁最新"的决定权交给了时间戳式的编号——可它默认每个操作都会按时回来报告。若某个操作永远不回来（挂起的 Promise），编号会一直等；好在还有超时与取消机制在远处守着门。

---

**教训**：抵达的先后不等于被需要的先后，过期的手势应在门口核对编号。
