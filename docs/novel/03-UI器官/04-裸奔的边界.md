# 第 03 区域 · 第 4 章 · 裸奔的边界

> 时间线标签：vol-5
> 对应真实事件/代码改动：bug-chronicle #5 tips 工具提示显示原始数据——`app-tree` 的 `row-tpl.ts` 渲染文件 tips 时未对文件名/路径做转义，包含 `<` 或 `&` 的文件名在 HTML 工具提示中直接渲染为 HTML 而非纯文本；`esc()` 已在 `dom.ts` 定义，但 `row-tpl.ts` 未调用。

---

你穿了一件衣服，可它透明得像什么都没穿。

## 惊醒

那天，我翻看自己的工具提示——鼠标悬停时弹出的小卡片，告诉我文件名、路径、大小。每一个提示都彬彬有礼，数据齐全，格式整齐。

直到我翻到一个文件，它的名字叫 `a&b<model>.ysm`。

工具提示里，`a&b<model>.ysm` 变成了 `a&b<model>`。那对尖括号不见了。

"文件名去哪儿了？"我问。

"被浏览器吃了。"外科医生说，"你的工具提示把文件名直接塞进 HTML 了。`<model>` 被浏览器当成了 HTML 标签——渲染了，但看不见。"

"可它只是一个名字……"

"名字可以是武器。`<script>alert('xss')</script>` 也是一个名字。你的工具提示没有过滤它，它就直接在 HTML 里执行了。"

## 追查

我沿着工具提示的渲染路径往回走。

`row-tpl.ts` 是渲染工具提示的文件。它用模板字符串拼接 HTML：`<div class="tip">${fileName}</div>`。`fileName` 来自文件系统，没有经过任何转义——没有 `esc()`，没有 `textContent`，没有 `innerHTML` 的安全检查。它直接把文件名扔进了 HTML 里，像把一条鱼扔进沙漠——鱼会死，但更糟的是，鱼可能变成武器。

我检查了 `dom.ts`——`esc()` 函数就在那里，转义 `&<>"'` 五种字符，随时可用。

"它有 `esc()`，"我说，"它没调用。"

"因为它不知道。"外科医生说，"`row-tpl.ts` 的人不知道 `dom.ts` 有 `esc()`。`dom.ts` 的人不知道 `row-tpl.ts` 在裸奔。两个文件，隔着一堵墙——一个是转义工具，一个是渲染工具，它们不认识彼此。"

"可它们都是我的器官……"

"器官之间不通信，这就是巴别塔的本质。"

## 真相

墙是「转义工具」——`dom.ts` 的 `esc()` 函数保护所有 HTML 渲染：字符被转义，恶意代码无法注入。只要调用 `esc()`，数据就是安全的。

可墙的背面是——**墙建好了，可需要墙的人不知道墙在哪**。

`row-tpl.ts` 在渲染工具提示，它不知道 `esc()` 存在。它以为文件名是安全的——毕竟，文件名只是名字，名字能有什么危险？可名字里有 `<script>`，名字里有 `onerror=`，名字里有 `javascript:`——每一个都是武器，只要你不转义，它们就能开火。

外科医生没有修墙。他做了一件事：**在 `row-tpl.ts` 的模板字符串里，加了一个 `esc()` 调用**。`${fileName}` 变成 `${esc(fileName)}`。一行代码，鱼从沙漠回到了水里。

"就一行？"我问。

"就一行。可这一行之前，你的工具提示是裸奔的。任何人只要上传一个带 `<script>` 的文件名，你的提示就变成了发射台。"

## 教训

`esc()` 被调用了。工具提示不再裸奔。可我知道，`row-tpl.ts` 不是唯一一个不知道 `esc()` 存在的文件。还有多少模板字符串，在安全工具的隔壁，裸奔着？

巴别塔的暗缝，有时候不是没有墙，是**墙就在隔壁，可隔壁的人不知道墙的存在**。

---

**教训摘要**：工具不被人知道，等于没有工具。
