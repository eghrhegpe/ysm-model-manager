## 一 · 咬死的齿轮

`DownloadQueue` 第一次意识到自己不对劲，是在一个测试框架里。

它被单独拎出来，想跑一个测试。它发现自己动弹不得——它的左手攥着 `App` 的衣领，右手攥着 `App` 的袖子，而 `App` 也攥着它。两个对象互相抓着对方，像一对咬死的齿轮。

「你先松手。」测试框架说。

「我松不了，」`DownloadQueue` 低头看了看自己的手，「我调 `downloadFileWithQueue` 要找他，发事件要找他，写日志要找他。他是我的一切。」

「那你让 `App` 先松手？」

「他更松不了，」旁边有人叹气，「他 `NewDownloadQueue(a)` 的时候就把我攥在怀里了。我们生下来就是拴在一起的。」

于是 `internal/app` 这个包成了全仓库唯一一个**跑不了测试**的包。24 个 Go 包，21 个有测试，3 个没有——`app_download.go` 是那 3 个之一，而且它的问题最优雅：不是代码难测，是**两个对象互相攥着，谁都不肯先松手**。

ADR-002 早就把这条债记下了，编号 P1，备注写得像病历：

> `DownloadQueue ↔ App` 循环引用——建议 callback 化，解锁独立测试。

病历躺在档案里。两个齿轮继续咬死在一起。

## 二 · 三个约定

转机来自一个很简单的问题——外科医生站在白板前问：

「你到底需要 `App` 的什么？」

`DownloadQueue` 想了一会儿，掰着手指头数：`downloadFileWithQueue` 帮我下载，`Event.Emit` 帮我喊话，`AddOpLog` 帮我记账。

「就这三样？」

「……就这三样。」

「那你不需要 `App`，」外科医生在白板上写下三个词，「你需要**三个约定**。」

于是 `DownloadQueue` 被松开了。

它的手上不再攥着谁，取而代之的是三张写着承诺的纸条：

```
downloadFn —— 下载的事，交给你了
emitFn     —— 喊话的事，交给你了
logFn      —— 记账的事，交给你了
```

构造它的人不再必须是一个叫 `App` 的庞然大物——任何能兑现这三张纸条的人都可以。`App` 在启动时把自己的三个本事写成纸条递过去，仅此而已。

改动比想象中安静：`struct` 里删掉 `app *App`，加上三个函数字段；`NewDownloadQueue` 的签名从「接住一个 App」变成「收下三张纸条」；`process` 里 7 处 `q.app` 全部换成 `q.downloadFn` / `q.emitFn` / `q.logFn`。

有一个插曲：改完编译，红了。

`internal\app\app_download.go:106: q.app undefined`

第 7 处 `q.app` 藏在 `process` 的 `defer` 里——那行发 `done` 事件的代码，平时几乎不会被注意到，可它确确实实攥着 `App`。外科医生找到它的时候说了句：「漏掉的往往是最不显眼的那个。」补上之后，编译绿了。

## 三 · 绳子解开之后

绳子解开的第一天，`internal/app` 有了第一个测试文件。

三个用例，安静地站在那儿：

```
顺序处理两个任务          —— 下载 A，再下载 B
失败不中断队列            —— 第一个坏了，第二个照常
取消后不发 done           —— 停下的齿轮，不该再喊"我转完了"
```

`DownloadQueue` 第一次被单独摆上台面，没有 `App` 在旁边替它圆场。它发现自己其实早就学会了怎么干活——只是以前每次干活都要先回头确认那根绳子还在。

「你知道吗，」它对 `App` 说，「我以为离开你我活不了。」

「你现在活得好好的，」`App` 说，「而且比我攥着你的时候跑得更干净。」

它俩对视了一眼，都没提那根绳子。绳子已经变成了三张纸条，而纸条是可以在别处再写一份的——下一个需要队列的宿主，不必再叫 `App`。

## 尾声

`DownloadQueue` 后来常常想起那个测试框架里的早晨。

它想：最结实的联结，不是两个对象互相攥着对方的衣领——那只是看起来牢靠，实际上谁想转身，都会把对方拽得一个踉跄。真正牢靠的联结，是各自手里有一份**对方可以兑现的承诺**，彼此心照不宣，转身不必回头。

`internal/app` 的测试统计从那天的 21/24 变成了 22/24。不多，但那是它第一次能用「自己」的名义跑完一整个用例。

它把三张纸条整整齐齐放好。

——它们比任何一条绳子都长。

**缝**：解耦的代价是信任——你不再攥着对方，就必须相信对方会兑现约定。而约定的兑现与否，没有任何物理力量保证，只有写下的那行签名和后来的每一个测试。

---

**教训**：最结实的联结是各执一份承诺，而不是互相攥紧。
