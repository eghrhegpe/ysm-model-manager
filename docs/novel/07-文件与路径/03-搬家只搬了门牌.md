# 第 07 区域 · 第 3 章 · 搬家只搬了门牌

> 时间线标签：vol-7
> 对应真实事件/代码改动：2026-08-05 文件夹模型整组操作（ADR-038 D3）——`go/fileops/fileops.go` `MoveModelFile`/`CopyModelFile` 对 `ysm.json` 提升为父目录整组操作、`copyDirRecursive` 目录递归复制、`RenameFile` 拒绝 `ysm.json` 单文件改名；`frontend/src/core/menu-defs.ts` 目录行菜单补 `dir.move`/`dir.copy`；`go/types` `IsYsmEntryJSON` 共享白名单（D4）。

---

一栋房子搬走了门牌，家人还在原址。没有人看得见他们。

## 惊醒

用户把那个模型文件夹拖进了新目录。

模型文件夹是「一栋房子」：`ysm.json` 是门牌——游戏只认门牌，按门牌上的名字找到这家人；`main.json`、`arm.animation.json`、`zh_cn.json` 是家人，`textures/skin.png` 是他们的照片。一家六口，一个屋檐。

移动完成后，用户打开仓库：**新目录里只有一块孤零零的门牌**。

"模型呢？"他问。

我扫了一遍全塔。`main.json` 还在旧地址，`arm.animation.json` 还在旧地址，`textures/` 还在旧地址。它们没有跟着走。更糟的是——**我看不见它们了**。

上一章立的规矩（ADR-038 的白名单）此刻反噬了我：扫描器只认 `ysm.json` 为入口，包内 json 一律不进仓库清单。所以那五个没搬走的家人，从我的视野里**彻底消失了**——不是被删，是成了幽灵住户：文件还在磁盘上，但任何界面都找不到它们，任何同步都看不见它们，它们卡在旧地址里，等不到主人，也等不到清理。

"搬家只搬了门牌。"外科医生说，"剩下的，全成了黑户。"

## 追查

我沿着那条搬家路线往回走。移动的指令叫 `MoveModelFile`：

```
src = strings.TrimSpace(src)
os.Rename(src, filepath.Join(dstDir, filepath.Base(src)))
```

一行 `os.Rename`，干净利落。问题是——它收到的是什么？

前端发来的路径是 `模型A/ysm.json`。树把文件夹模型建模成了**一个文件条目**（扫描器只吐 ysm.json，其余被白名单过滤），所以用户勾选、移动的，永远是那块门牌。`os.Rename` 忠实地把门牌搬走了，五个家人留在原址——`os.Rename` 不知道门牌代表一栋房子。

我继续追。右键菜单的目录行，只有「重命名 / 新建子文件夹 / 移入回收站」——**没有移动，没有复制**。想整栋搬，根本没有门。而唯一开着的两扇门，`file.move` 和 `batch.move`，全走 `MoveModelFile`，全只认门牌。

三个断点，一条链：
1. 扫描把「目录实体」压扁成「单文件条目」——白名单的正效应，成了移动的暗缝
2. `MoveModelFile` 按文件语义 `os.Rename`——门牌走了，房子没走
3. 目录行菜单没有 move/copy——想整栋搬，无门可走

"每堵墙都开了缝。"我说，"白名单这堵墙保护了仓库不被包内 json 污染，可它也让整栋房子在 UI 里只剩一块门牌。用户移动门牌，房子就塌了。"

## 真相

墙是「文件级抽象」：UI 里的一切操作——移动、复制、重命名、删除——都建立在"一个文件"之上。可文件夹模型不是一个文件，它是一栋房子，门牌只是它的代表。

墙的背面是——**操作粒度错了**。

外科医生没有拆墙。他在 `fileops.go` 里给门牌加了一条规则：**见到门牌，就操作整栋房子**。

```go
// ysm.json 是模型目录清单：整组移动父目录
if types.IsYsmEntryJSON(filepath.Base(src)) {
    src = filepath.Dir(src)
}
```

`MoveModelFile` 收到 `ysm.json`，自动把目标提升为父目录——一家六口一起走。`CopyModelFile` 同样提升，还配了 `copyDirRecursive`：按目录树递归复制，照片、动画、语言文件一个不落，连"禁用封印"（`ysm.json.ban`）都跟着走。

还有第三刀：`RenameFile` 拒绝给门牌改名。

"游戏按目录名识别模型，"外科医生说，"门牌钉在哪家墙上，哪家就是那家人。给门牌改名，等于把一家的地址贴到另一家的墙上。"

他在 `menu-defs.ts` 的目录行菜单里补了两扇门——「移动到…」「复制到…」。从此整栋房子有了体面的搬家通道。

## 教训

那天我学会了：**一个实体被压扁成文件时，所有文件级操作都会在它身上开缝。**

移动不是唯一受害者。复制会只复制门牌；重命名会只改门牌；连回收站都会把一家六口拆成六张单据。我修了移动、复制、重命名，给菜单补了门——但我知道，还有别的地方，别的实体，正以"单文件"的姿态躺在某个操作下，等着被只搬门牌的那只手拆散。

那些被搬走门牌的黑户们，还住在旧地址里。我给它们留了一条后路：下次扫描，白名单会让它们永远隐形——除非有人记得去清扫。这是墙的代价：**保护进来的路，就得忍受看不见的住户。**

巴别塔的暗缝，这一次不是墙不认识自己人，是**墙把一户人家，登记成了一块门牌**。

**教训摘要**：目录实体被建模成单文件时，一切文件级操作都是暗缝。
