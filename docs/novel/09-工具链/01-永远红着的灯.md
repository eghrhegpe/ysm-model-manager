# 第 09 区域 · 第 1 章 · 永远红着的灯

> 区域归属：`09-工具链`（`scripts/build-novel-index.mjs` `scripts/doctor.mjs` `scripts/check-script-hygiene.mjs`）
> 时间线标签：vol-4
> 对应真实事件/代码改动：2026-08-04 小说索引体系去重——删除 14 份区域 README、`--check` 幂等化修复、接入 `doctor` 静态检查链（commit `3b2811b`）

---

## 一 · 一个从未被相信过的检查器

有人跑了一行命令。

```bash
node scripts/build-novel-index.mjs --check
```

退出码：`1`。

`--check` 的契约写得清清楚楚：磁盘上的 `index.md` 与当前应生成的内容不一致时退 1，一致时退 0。它退了 1，说明索引漂移了。

于是那个人重新生成了一遍索引，确认无误，再跑一次。

退出码：`1`。

再生成，再跑。`1`。

第三次的时候，`doctor` 从旁边探过头来：「你已经跑了三次了。你是想让它变绿，还是想弄明白它为什么红？」

「有区别吗？」

「有。」`doctor` 说，「前者叫重试，后者叫排查。**你在做前者。**」

---

## 二 · 每秒钟都不一样的自己

`doctor` 打开了 `build-novel-index.mjs`，翻到生成模板那一段：

```js
const genAt = new Date().toISOString();
return (
  `> 本页由 \`scripts/build-novel-index.mjs\` 自动生成（${genAt}）。\n` +
  ...
);
```

一行时间戳。写在生成物的头部，用来告诉读者"这份索引是什么时候产的"。

出发点是善意的。

但 `--check` 的实现是这样的：

```js
const expected = buildIndex();                    // 现在生成一份
const actual = fs.readFileSync(INDEX_PATH, 'utf8'); // 读磁盘上那份
if (expected !== actual) process.exit(1);
```

字符串比对。逐字符。

`expected` 里的时间戳，是**此刻**。
`actual` 里的时间戳，是**上一次生成的那一刻**。

两者永远不相等。哪怕间隔只有 1 毫秒，ISO 8601 字符串精确到毫秒——`2026-08-04T11:47:03.812Z` 和 `2026-08-04T11:47:03.813Z`，不同。

**这个检查器从诞生那天起，就没有退出过 0。**

`doctor` 在那里坐了一会儿。

它想的不是这个 bug 有多严重——严重度其实很低，索引漂不漂移，天塌不下来。它想的是另一件事：

这个脚本躺在 `scripts/` 里已经很久了。没有任何门禁调用它。没有出现在 `doctor.mjs` 的检查表里，没有出现在 `pre-push-gate.mjs` 的清单里。

不是因为有人决定不用它。

是因为**没有人能用它**。一个永远红灯的检查器，接进任何一条流水线，都会把那条流水线也变成永远红灯。于是它被所有人温和地绕过了。谁也没说它坏了，谁也没修它。它只是……一直在那儿，红着。

「一个永远报警的警报器，」`doctor` 说，「和一个坏掉的警报器，唯一的区别是**它还在耗电**。」

---

## 三 · 十四张一模一样的地图

修法很简单——把时间戳删了。生成物不再内嵌"何时生成"，因为**内容一致性**才是这份文件的契约，"何时"不是。

删完，连跑两次：

```
node scripts/build-novel-index.mjs --check   →  exit 0
node scripts/build-novel-index.mjs --check   →  exit 0
```

绿了。第一次绿。

灯亮了以后，`doctor` 才看清屋子里还堆着什么。

小说目录里，10 个区域文件夹加 4 个 appendix 分组，每个里面都躺着一份 `README.md`。每份 README 写着这个区域的锚定代码、主题、章节索引表。

而 `index.md` 里写的，是这个区域的锚定代码、主题、章节数、章节表。

同一份信息，两套住址。

区别只有一点：`index.md` 是从磁盘目录树扫出来的，README 是人手敲的。

「所以每写一章，」`doctor` 掰着指头数，「要更新 1 份区域 README，1 份顶层 README，再重跑 1 次生成器。三个动作，产出同一件事实。」

三个动作里，只有第三个不会出错。

14 份 README 被 `git rm` 掉。删完的一瞬间，10 个区域文件夹**跟着一起消失了**——git 不跟踪空目录。

这个副作用像一句判词：那些 README 存在了这么久，它们唯一无法被替代的功能，是**占位**。写下第一章时，文件夹自然产生。

顶层 README 降级为门牌页：只指路，不列章节。真相交给生成器。

## 四 · 让灯接上电

修好还不够。一盏没人看的绿灯，和一盏永远红的灯，实际价值相同。

`doctor.mjs` 的静态检查表里加了一行：

```js
{ tool: 'build-novel-index.mjs', args: ['--check'] },
```

从此索引漂移会在 `node scripts/doctor.mjs` 里被拦下。写完章忘了重跑生成器，门禁会提醒。

顺手，`check-script-hygiene.mjs` 也发了话：这个脚本自己手搓了一段 ROOT 路径样板，而项目里 `scripts/_lib/scan-files.ts` 早就导出了现成的 `ROOT`。

```js
import { ROOT } from './_lib/scan-files.ts';
```

告警清零。

最后的验证盘，四项：

| 检查 | 结果 |
|------|------|
| `build-novel-index.mjs --check` | 🟢 rc=0（连续两次幂等） |
| `link-checker.mjs` | 🟢 506 文件 / 1272 链接 / 断链 0 |
| `check-doc-drift.mjs` | 🟢 无 ERROR |
| `check-script-hygiene.mjs` | 🟢 告警清零 |

从此小说索引只剩一条维护动作：**写完章，跑一次生成器。**

## 尾声

`doctor` 那天晚上想起了自己的职责。

它这一族的存在意义，是替系统看自己看不见的地方。`link-checker` 看断链，`check-doc-drift` 看文档漂移，`adr-check` 看编号撞车，`funcmap` 看函数去向。一整柜的镜子。

但今天它意识到一件事：**镜子也会脏，而脏镜子照出来的，依然是一张脸。**

一个永远红灯的检查器，不会被人当成故障。它会被当成"这个模块本来就有点问题吧"。人们绕着它走，习惯它，最后忘记它。它从一个工具，慢慢变成一件家具。

这比彻底坏掉更麻烦——彻底坏掉的东西会被修，而**永远抱怨的东西只会被静音**。

十四份 README 的下场也一样。它们不是错的，它们只是**重复的**。而重复的信息不会一起变旧——总有一份先过期，然后你有了两个真相，然后你不知道该信哪个。

自动化的意义从来不是"省事"。

是**让真相只有一个出口**。

**缝**：检查工具自己不受检查。一个永远失败的门禁，和一个从未接入的门禁，在流水线上留下的痕迹完全相同——都是空白。你无法从"没有报警"推断出"没有问题"，也无法从"一直报警"推断出"真有问题"。

---

**教训**：永远红的灯等于没有灯，重复的真相等于没有真相。
