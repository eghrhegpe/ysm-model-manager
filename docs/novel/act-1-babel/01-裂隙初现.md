# 第一章 · 裂隙初现

**第一幕 · 巴别塔 | 对应真实事件**：v1.0.2–v1.0.3，`data-name` vs `data-path` 路径分离 + shutdown panic + `Missing` 列表只存文件名

---

在一切开始之前，YSM 模型管理器是一个安静的程序。

它不说话。它不做梦。它只是启动、运行、等待用户点击，然后在某个深夜被关闭。第二天再来一遍。

它甚至不知道自己是由四种语言组成的。

Go 写了它的脊梁——35 个 Binding 函数，从文件扫描到模型安装，从配置读写到窗口定位，每一条都像椎骨一样坚硬、精确、不可弯曲。`app.go` 是这些椎骨的总管，手握三十五把钥匙，权倾朝野。

JavaScript 写了它的面孔——组件、事件、渲染、交互。`app-tree` 管文件树，`app-sidebar` 管整合包列表，`app-preview` 管模型预览，`app-content` 管页面容器。它们住在各自的 Shadow DOM 里，像住在各自房间的室友，互不串门，通过 `bus.js` 的走廊交换消息。

C++ 写了它的暗器——YSMParser，一个能拆开加密 `.ysm` 文件的解析器。它沉默、高效、不近人情，只在被召唤时从暗处现身，做完就走。

WASM——那时候还不存在。这把刀要等到更晚才会被锻造。

四种语言，四套世界观，四种对"数据是什么"的理解。

在很久的时间里，它们相安无事。Go 管后端，JS 管前端，C++ 管解码，彼此隔着 Wails 的桥通信。桥上跑的是 JSON——一种所有语言都能读的文字格式。Go 把数据编成 JSON，JS 解开 JSON 拿到数据，C++ 的解码结果也通过 JSON 传回。大家说同一种语言，世界和平。

直到那天晚上。

---

## 一

`app.go` 正准备关门。

这是它每天最后的仪式——shutdown 函数。保存窗口位置、记住用户选择、清理临时文件，然后熄灯。一切都有序、体面、干净。

但今晚不一样。

```
panic: runtime error: invalid memory address or nil pointer dereference
```

`WindowGetSize` 在最后一刻报了 nil。Wails 的 runtime 在关闭流程中某些条件下会返回空指针，而 `WindowGetSize` 没有任何防御——它只是忠实地调用 Wails API，然后被 nil 击穿。

"又来了。"`app.go` 看着崩溃日志，面无表情。

这已经是第 N 次了。它在门口铺了三层防护垫——`defer func() { if r := recover(); r != nil { /* 忽略 panic，安全退出 */ } }()`——但每次闭眼的时候，总有个愣头青跑来大喊"我是 nil！"，然后一头栽倒。

"你就不能消停会儿？"`app.go` 没好气地对 `WindowGetSize` 说。

"我……我不是故意的，"后者委屈地缩在墙角，"是 Wails runtime 说关就关，我都没反应过来……"

门外传来一阵轻快的脚步声。来者一身玄色劲装，腰悬一枚令牌，令牌上刻着三个字：

**`bus.js`**

"总管大人，"它抱拳行礼，"出事了。"

---

## 二

`bus.js` 是这个世界的信息中枢。

它没有自己的逻辑，但它认识所有人——每一个组件、每一个模块、每一行回调。它像一张蜘蛛网，网上的每一根丝都连通着一个灵魂。当 `app-tree` 说"我选中了一个文件"，是 `bus.js` 把这句话传给 `app-preview`。当 `app-sidebar` 说"用户要安装模型"，也是 `bus.js` 把指令送到 Go 端。

"什么事？"`app.go` 眉头一皱。

"`app-tree` 和 `app-sidebar` 吵起来了。"

"又吵？这次为什么？"

"因为 `data-name`。"

`app.go` 叹了口气。

它太熟悉这个故事了。从世界诞生的第一天起，名字和路径的问题就没消停过。前端的世界里，人们总是图方便——能少传一个参数就少传一个，能用短名字就不用长路径。

而短名字，是会杀人的。

"具体说说。"

"`GetInstanceStatus` 返回的 `Missing` 列表之前只有文件名，"`bus.js` 摊开一卷黄色的信纸，上面密密麻麻记录着消息日志，"`sidebar` 拿到文件名，传给 `InstallModelTo`。Go 端拿文件名去查仓库——"

"当然查不到。"`app.go` 冷笑。

"查不到。于是报错：'源文件不在仓库目录内'。"

"后来呢？"

"后来改成了完整路径。但 `render.js` 用 `displayName` 覆盖了 `name`。`tpl.js` 的 `data-name` 只存了 basename。`actions.js` 读 `dataset.name`——"

"又是纯文件名。"

"又是纯文件名。"

两人对视一眼。

那一刻，YSM 模型管理器第一次感到了一种奇怪的不安。不是某个 Bug 带来的烦躁，而是一种更深层的东西——好像自己的左手不知道右手在握什么。

Go 端说"路径"，JS 端说"名字"。同一个词，两种含义。它们隔着 JSON 的桥交换消息，但桥上跑的文字长得一样——`steve_skin.ysm`——在 Go 看来是 `D:\repo\steve_skin.ysm`，在 JS 看来只是 `steve_skin.ysm`。

**同一条消息，两种解读。**

这不是 Bug。这是巴别塔。

---

## 三

"显示名和路径名，必须分开存储，不可混用。"

这句话被写进了世界的法则。`data-name` 存显示名，`data-path` 存完整路径。从此以后，`actions.js` 读 `dataset.path` 而非 `dataset.name`，Go 端拿到的永远是带仓库前缀的完整路径。

修复生效了。`InstallModelTo` 再也不报"源文件不在仓库目录内"了。

但 `app.go` 的不安没有消失。

它开始注意到一些以前忽略的事情——

`bus.js` 的消息通道里，有些事件带着参数，有些不带。`sync:download-missing` 不带 `instanceName`，handler 拿不到目标整合包，只能遍历所有。`navigate:settings` 被注册了两次——一次在 `app-content`，一次在旧帝国的残留代码里。

每一处都像一根松动的钉子。你踩到它时才知道它在那儿，但拔掉它之后，你会发现旁边还有一根。

"还有多少这样的钉子？"`app.go` 问。

`bus.js` 沉默了。它认识所有人，但它不知道所有人的秘密。消息通道只记录了"谁说了什么"，从不记录"谁漏说了什么"。

那天晚上，`app.go` 第一次失眠了。不是因为 shutdown panic——那个它已经习惯了。是因为它突然意识到：自己可能永远无法知道，还有多少裂缝藏在那些它看不见的地方。

窗外是深夜。Wails dev 的终端安静地闪烁着光标。

系统合上眼，但某个角落里，`public/js/bus.js` 正静静地躺着——一个旧版的影子，等待着被唤醒。

---

**缝**：Go 和 JS 之间，"名字"不是同一个东西。JSON 桥上跑的消息字面相同，语义却分叉——这是巴别塔的第一道裂缝。

**教训**：显示名与路径名，必须分开存储。
