# 第六章 · 影子叛乱

**第二幕 · 筑墙者 | 对应真实事件**：v1.4.1–v1.4.5，Shadow DOM CSS 变量失效 + 按钮穿透不了 + 事件名不匹配 + `adoptedStyleSheets` 不继承 `var(--accent)` + 选中高亮消失

---

沙箱的诅咒让系统明白了：墙的两边，数据长不一样。

但沙箱是 Go 和 C++ 之间的墙，普通用户看不见它。用户能看见的墙只有一面——Shadow DOM。

这面墙立在眼前。你能看到按钮，你能摸到按钮，但你**点不到按钮**。

---

## 一 · 按钮去哪儿了

用户发来一条让人心头一紧的消息：

**"整合包管理的安装按钮失效了，顺带检查一键安装模型等按钮是否失效"**

点一下安装按钮——没反应。再点——还是没反应。控制台没有报错。`console.log` 打了——没执行。

按钮在页面上看得到，摸得着，有颜色有文字，像一个正常人。但点击它的时候，没有任何东西发生。

`btn-install-one` 的事件绑定在 `app-sidebar/events.js` 里。按钮渲染在 `app-content/tpl.js` 里。

`app-sidebar` 的 `querySelector` 可以在自己的 Shadow DOM 里找到任何元素——但**永远找不到** `app-content` Shadow DOM 里的按钮。因为 Shadow DOM 的边界是不可穿透的——就像两栋独立的大楼，一栋的人看不到另一栋的房间号。

事件绑定从 `app-sidebar/events.js` 搬到了 `app-content/index.js`——按钮所在的大楼。

然后按钮响应了。

但卡住了。点击后显示「⏳ 导入中」，然后永远「⏳ 导入中」。

"按钮恢复的逻辑呢？"

"sidebar 在监听 `queue:status` 事件说'完成了'，但 app-content 发的是 `sync:download-complete`。"

**张三签收的包裹，快递员在喊李四的名字。**

`bus.emit` 和 `bus.on` 是两个隔了三个文件、两位作者、两天时间写下的两行文字。一个叫它「张三」，一个叫它「李四」。`bus.js` 记录了所有消息，但它不会告诉你张三和李四是同一个人。

修复后，所有按钮恢复事件统一为 `sync:download-complete`，且**只用 `finally` 发送**。

写进战斗手册的铁律：异步操作完成后的 emit 只放 finally，不放 try 末尾。

## 二 · 颜色的迷踪

按钮活了，但它没有颜色。

"按钮没有主题色。"用户说。

合理的需求。按钮用的是浏览器默认样式——灰色背景、黑色文字，放在赛博霓虹主题里像一块补丁。只需要加一行 CSS：

```css
.btn.accent {
    color: var(--accent);
}
```

变数出在 `var(--accent)` 上。

CSS 自定义属性会沿着 DOM 树自然继承。你在 `:root` 上定义 `--accent: #66d9ef`，子元素里的 `var(--accent)` 就能取到这个值。这是 CSS 规范写了的事情。

但"规范写了"和"浏览器做到了"之间，隔着一层 Shadow DOM。

应用用了 Web Components + Shadow DOM，并且用了 `adoptedStyleSheets`——Chrome 73 引入的新 API，允许 JS 直接把 CSSStyleSheet 对象关联到 Shadow Root 上，比传统的 `style` 标签更高效。

高效是高效，但它有一个致命的坑：**`adoptedStyleSheets` 里的 `var()` 不继承文档的 CSS 自定义属性。**

至少在这个项目依赖的 WebView2 版本里是这样。

两个小时。CSS 类选择器试了，不行。内联样式试了，也不行。按钮在所有主题下都显示同一副模样——没有颜色，没有灵魂。

最终回到最朴素的方案：硬编码 + `:host-context()` 主题适配。

```css
.hdr-btn.accent {
    background: #7c83ff33;
    color: #66d9ef;
    border-color: #7c83ff55;
}
:host-context(.theme-warm) .hdr-btn.accent {
    color: #8b4513;
}
```

硬编码不优雅。但它工作。

**有时候最"正确"的方案（CSS 变量 + adoptedStyleSheets）反而不如最"朴素"的方案（硬编码）可靠。** Web 标准很美，但浏览器的实现总是慢标准一步。

## 三 · 选中高亮消失

蓝色不见了。

选中文件时，那一抹蓝色高亮——`.fl.selected { background: ... }`——消失了。

旧帝国时代，每次 `_renderTree()` 之后，`bindTreeEvents` 会遍历所有 `.fl` 元素，读取 `data-fullpath`，和 `selectState.keys` 里的路径比对，匹配的就加上 `.selected`。

但虚拟滚动时代，`bindTreeEvents` 只调用一次——通过事件委托捕获所有点击。它不再在渲染后遍历元素了。

而那本该出现在 `.fl` 上的 `.selected`，被写进了 `flattenVisible` 生成的 HTML 字符串里——然后被塞进了 `span class="nm"`，而不是 `div class="fl"`。

CSS 规则是 `.fl.selected { background: ... }`。类在 `nm` 上，规则在 `fl` 上。两者像两条永不相交的平行线。

"所以高亮就没了？"

"没了。"

修复是把 `.selected` 从 `nmCls` 里抽出来，变成独立的 `rowCls`，直接渲染在 `div class="fl"` 上。

那道蓝色又回来了。但它暴露了一个更深的问题——`selectState.keys` 里存的是绝对路径（`data-fullpath`），而 `flattenVisible` 里比对的是相对路径（`full`）。两者从来就不相等。即使没有虚拟滚动，选中高亮也从来不是靠 HTML 字符串保证的——它靠的是每次渲染后的人工巡检。

**一个从一开始就错位的设计，被一次重构彻底曝光。**

## 四 · 反噬

`app.go` 站在 Shadow DOM 的废墟上，回望这一天的全部战况。

按钮看得到点不到——事件绑定的房间和按钮的房间不在同一栋楼。
CSS 变量不继承——`adoptedStyleSheets` 的墙把文档的自定义属性挡在了外面。
选中高亮消失——虚拟滚动改变了 DOM 结构，但 CSS 规则还在找旧的元素。

三件事，一个根源：**Shadow DOM 保护了组件的内部不受外部干扰，但"不受干扰"也意味着"不受帮助"。**

CSS 变量是帮助——它让主题色从根节点流到叶子节点。Shadow DOM 挡住了它。
事件委托是帮助——它让一个监听器管理所有按钮。Shadow DOM 挡住了它。
全局状态是帮助——它让选中状态在渲染后自动恢复。Shadow DOM 挡住了它。

挡住了干扰，也挡住了帮助。这就是隔离的反噬。

而反噬的可怕之处在于——它**不报错**。

CSS 变量不继承时，浏览器不抛异常。按钮的事件绑在另一个 Shadow DOM 时，`querySelector` 返回 null 而不是报错。选中高亮消失时，CSS 规则静静地找不到匹配元素，什么也不说。

**没有错误信息。只有沉默的失败。**

比沙箱的八轮 Debug 更让人绝望——沙箱至少有报错（`Unsupported file version`），你可以从报错倒推。Shadow DOM 连报错都没有，你只能从"什么都没发生"这个虚无中摸索真相。

`app.go` 在日志里写道：

**"Shadow DOM 的墙是单向玻璃——外面看得见里面，里面看不见外面。而开发者站在外面，以为自己什么都看见了。"**

---

**缝**：Shadow DOM 隔离了样式和 DOM，但连 CSS 变量的继承、事件的传播、状态的同步也一并隔离了。保护了安全，连功能也保护掉了。不报错，只沉默。

**教训**：按钮所在的大楼就是事件绑定的大楼。
