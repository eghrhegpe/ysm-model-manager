# 第七章 · 六脉归一

**第二幕 · 筑墙者 | 对应真实事件**：v1.5.0–v1.5.2，6 种资源类型统一 + 虚拟滚动丢行 + `inited` 缓存黑洞 + 符号链接路径写死 + 进度条消失太快 + `.json` 被所有链路无视

---

在所有筑墙的行为中，最雄心勃勃的是这一次：把六种完全不同的东西，塞进同一套系统。

YSM 模型、MMD 皮肤、VRChat 头像、材质包、光影包、机械动力蓝图——六种资源类型，六套几乎一样的界面，六个各自为政的目录路径，六份散落在代码各处的推送逻辑。

"这不就是六个手指头吗？"`resource_types.json` 说，"各管各的，谁也不服谁。"

`resource_types.json` 是一张刚诞生的清单。60 行 JSON，但它定义了一切——每个类型的名字、图标、扩展名、安装目录、导入策略。所有组件都读它，按它的规则行事。

六种剑气，一套心法。这就是通用化的第一步。

但通用化——消灭六套重复逻辑——本身也是一堵新墙。你把六个入口合并成一个，新的入口必须理解六种不同的语义。理解不了，就出错。

---

## 一 · 虚拟森林

文件树的 DOM 节点太多了。几千个 `.ysm` 文件同时渲染时，`app-tree` 的 `innerHTML` 要输出几万个 `div`。浏览器吃不消——滚动卡顿、内存飙升、触摸板像在泥潭里滑动。

`virtual-scroll.js` 是一位路过的工匠。它身材瘦小，口袋里只揣着两样东西：一把尺（`ROW_H = 28`）和一卷缓冲垫（`BUFFER = 15`）。

"你不需要把整片森林都种在眼前，"它说，"你只需要看到你脚下那几棵树。"

它把嵌套的文件夹层级拍平，变成一维的行数组。根据滚动条的位置，只渲染当前视口里能看到的那十几行。曾经卡成 PPT 的滚动，现在如丝般顺滑。

但虚拟滚动也是一堵新墙。它把 DOM 从"真实存在"变成了"按需存在"——你看到的才是真的，看不到的就不是。而旧代码的很多假设建立在"所有 DOM 都存在"之上。

选中高亮消失——因为 CSS 类被放在了错误的元素上。这个问题在旧代码里被人工巡检掩盖了，虚拟滚动揭开了伤疤。

v1.5.0 发布后不到一小时，用户的反馈就来了："虚拟滚动在某些文件夹里会丢行。"

展开一个 2000+ 文件的文件夹——显示的文件数只有实际的一半。`flattenVisible` 函数在展开/折叠子文件夹时重复计数，列表长度翻倍。

修复：展开前清空 `_flatCache`，强制重建拍平列表。

新墙修好了旧墙的问题，但新墙也开了自己的裂缝。

---

## 二 · 缓存黑洞

"'资源类型'子标签页做成了全宽横排导航，但之后换一个导航页再回来，子标签就消失了。"

这个问题藏在 `_bindTabs` 的逻辑中。`inited[tab]` 控制着 tab 的首次加载——一旦检测到 tab 已被初始化过，就跳过 render。

但跳过 render 不等于跳过 DOM 重建——当用户切换到另一个导航页再回来时，整个 Shadow DOM 被重建了。重建后，tab 容器是一个全新的 DOM 节点，旧的事件绑定全部丢失。但 `inited[tab]` 仍然是 `true`——所以 `_bindTabs` 认为不需要重新初始化。

**数据以为初始化过了，DOM 认为没初始化过。**

这是一个完美的缓存黑洞——缓存说"我做过了"，但被缓存的对象已经不存在了。就像你记得昨天把钥匙放在桌上，但桌子已经搬走了。

修复：`disconnectedCallback` 时重置 `inited` 对象。重建 DOM 后，所有 tab 重新初始化。

但 `inited` 的黑洞不是唯一一个。推送按钮也消失了——从资源管理器切到版本列表页面时，推送按钮不见踪影。根因同样是 Shadow DOM 重建后事件绑定丢失。

新墙创造了新的黑洞。统一创造了新的边界。六种类型走同一扇门，但门的开合逻辑比六个独立入口更复杂。

---

## 三 · 符号链接的沉默

"MMD 模型装了但游戏里看不到。"

用户在仓库里看到 MMD 文件树正常，点了安装，进度条走完，toast 显示"✅ 已安装"。但游戏里没有新皮肤。

日志：
```
[Install] 安装模式: symlink（推荐）
[Install] 目标: ...\resourcepacks\
[Install] ✅ 完成
```

文件装到了 `resourcepacks/`——而 MMD 皮肤的安装目录应该是 `versions/1.20.1-Fabric/custom/`。

`pushResourceToInstance` 的路径映射写死了 `custom/`。通用化的代价——不同的资源类型安装到不同的子目录，但通用函数只认一条路。

修复：`SubDirMap` 新增 `mmd-skin → resourcepacks/` 映射。

通用函数以为自己什么都能处理，但它不知道每种"什么"都有自己的家。YSM 住 `custom/`，MMD 住 `resourcepacks/`，光影包住 `shaderpacks/`——六种剑气，六个方向，一套心法必须知道每种剑气往哪飞。

---

## 四 · 进度条的焦虑

当用户点击"安装全部"时，所有缺失文件开始排队下载。每个文件下载完成后，按钮会刷新——但刷新后的按钮文本是「⬇️ 安装缺失 (N)」，而不是「✅ 已完成」。

下载队列右下角有一个进度条——但进度条在下载完成后就消失了。消失得太快。用户不知道队列是否真的执行完毕。

"进度条不是用来炫技的——是用来让用户安心的。"

修复：`cleanup` 函数里不再立即恢复按钮文本，先显示「✅ 完成」等 2 秒，再恢复。

---

## 五 · 解压的前夜

凌晨一点，日志里静静地躺着一条消息：

```
[YSM] 文件类型: .json
[YSM] 跳过：不支持的文件格式
```

用户解压的模型包里，`keya.ysm.json` 作为一个独立文件躺在仓库里。`ScanModelEntries` 的扩展名过滤列表中没有 `.json`。`ExtractYsmSummary` 没有 `.json` 分支。`AnalyzeBedrockModel` 也没有 `.json` 分支。

**所有处理链路都对 `.json` 视而不见。**

这条日志是一个预兆。六个小时后，用户在群里发了四个字：

"预览不了。"

但在这个凌晨一点，没有人在乎。系统不知道，用户不知道，连 `.json` 文件自己都不知道——它只是安安静静地躺在仓库里，等待天亮后被人双击，然后什么都看不到。

---

## 六

`app.go` 看着 v1.5.0 的发版说明，上面写着一行警告：

**此版本为架构重构过渡版，不推荐日常使用。**

六合一统消灭了六套重复逻辑。但新系统创造了六种新 Bug：虚拟滚动丢行、缓存黑洞、符号链接路径写死、进度条消失、按钮失踪、`.json` 被无视。

它想起了一件事——第一幕结束时，它以为最坏的裂缝是"同一条消息，两种解读"。但现在它知道了：

**消灭重复逻辑本身就是一堵新墙。** 你把六扇门合并成一扇，门的规则必须覆盖六种语义。覆盖不了，就出错。而出错的方式是新的——不是旧的 Bug 换了个壳，而是全新的、从未见过的、因统一而产生的裂缝。

统一是方向。但统一的代价是复杂度集中。以前六个手指各管各的，一个坏了不影响其他五个。现在一只手控制六个手指，手掌抽筋了，六个手指一起动不了。

`app.go` 在日志里写道：

**"通用化的墙把分散的裂缝聚拢成了集中的裂缝。以前是六处小伤，现在是一处大伤。"**

---

**缝**：统一消灭了重复，但把分散的裂缝聚拢成集中的裂缝——缓存黑洞、路径写死、类型无视，都是"一套规则管六种语义"的代价。

**教训**：六条路归一扇门，门必须认识每条路的家。
