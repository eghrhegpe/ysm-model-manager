# 第十四章 · 正名之书

**第三幕 · 绘图师 · 余响 | 对应真实事件**：v1.7.9–v1.7.12 + v1.8.0–v1.8.4，TERMINOLOGY.md 诞生 + page-store/dnd-state 模块提取 + DEPRECATED_NAMES.md + 赛博朋克网格动画 + 侧栏并发控制

---

上一章，系统给自己装上了统一的心跳。

四个过渡变量——`--tr-fast`、`--tr-normal`、`--tr-slow`、`--tr-enter`——让十二个心室用一个节奏跳动。`stagger.js` 的十二行代码让列表有了呼吸。三十多个 `.no-animations` 选择器让所有动画都可以被关闭。

心跳有了。脉搏有了。

但 `bus.js` 坐在自己的丝线上，感到一阵新的不安。

心跳可以统一，因为心跳是物理的——duration、easing、delay，这些数值可以被测量、比较、替换。但那些不能被测量的事——**名字**——要怎么办？

---

## 一 · 同一个词，两种意思

用户桌面上，一个 toast 弹了出来。

「请先设置游戏路径。」

这行字出现在右下角，停留两秒，淡出。没有人觉得它有什么问题。从第一章到今天，这条 toast 弹出过上百次，指导过每一位新用户。

但 `app-content` 盯着这句话，忽然觉得不对劲。

「设置？还是配置？」

它打开了自己的每一个组件。同样一条提示，在不同地方用的是不同的词：

- `handler-sync.js` 写的是「请先设置游戏路径」
- `handler-other.js` 写的也是「请先设置游戏路径」
- 但 `context-menus.js` 写的是「请先设置游戏根目录」
- 而 `download-queue.js` 写的是「请先在设置中配置仓库目录」

设置。配置。路径。根目录。仓库目录。

同一个意思——"用户忘了填某个必填项"。五种说法。

「这不是 Bug。」`app-content` 说。没有任何一个说法是错的。用户看到「请先设置游戏路径」会明白自己要做什么，看到「请先在设置中配置仓库目录」也会明白。每一个都正确，每一个都能引导用户到正确的页面。

但它们不是同一句话。

`app-content` 想起了第一章——Go 说"路径"，JS 说"名字"，同一条消息在 JSON 桥上跑过去，桥的两侧对这条消息的解读完全不同。`steve_skin.ysm`——Go 看来是 `D:\repo\steve_skin.ysm`，JS 看来只是文件名。

那是巴别塔的第一道裂缝。

而现在，它发现巴别塔的内部也是巴别塔。同一个器官对同一个概念用不同的词——不是因为它们不理解彼此，而是因为**从来没有一个地方正式说过什么是正确的词**。

## 二 · 七个名字

`app.go` 把清单铺在桌上。

清单的第一部分是"资源类型"——YSM、MMD、VRC、材质包、光影包、蓝图。六种文件类别，各有各的目录结构、扩展名白名单、同步策略。

在代码里，"资源类型"有几个名字？

```
rtype       — app.go、resource_bindings.go 中的参数名
_rtype      — app-sidebar/index.js 中的实例变量
resourceType — resource-types.js 中的导出常量名
rType       — oldest-models.js 中的局部变量名
type        — resource_types.json 中的键名
restype     — 某处旧代码中的参数名
resType     — 另一处旧代码中的参数名
```

七个名字。同一个东西。分布在十二个文件里。

没有一个名是错误的。`rtype` 短，适合 Go 的参数传参。`_rtype` 带下划线前缀，在 JS 中表示"私有实例变量"。`resourceType` 全拼，适合作为导出常量被其他模块 import。每一个选择在当时都是合理的——Go 喜欢短名，JS 喜欢驼峰，JSON 的规范要求小写不带任何特殊符号。

但七个名字意味着：你想搜"所有使用资源类型的地方"，你要用七个正则表达式。你用 `rg rtype` 搜到了 Go 端，漏了 `_rtype` 的 JS 端。你用 `rg resourceType` 搜到了 UI 渲染，漏了 `type` 的数据文件。

**名字的裂隙不在于"叫错了"——而在于"每一次叫对都是巧合"。**

`app.go` 继续往下看。

"仓库"。UI 里叫「仓库」——用户配置的根目录，下面有 `ysm/`、`resourcepacks/` 等子目录。Go 代码里叫 `FilesRoot`——配置路径。JS 变量名叫 `repo`——短，好拼。一个概念，三个名字。

"整合包"。UI 里叫「整合包」——用户安装的 Minecraft 实例列表。Go 代码里叫 `Instance`——Go 结构体的名字。JS 旧代码里叫 `pkg`——残留在注释和变量名里。Go 绑定函数叫 `ListVersionInstances`——暴露了底层 PCL/HMCL 的版本实例概念。一个概念，四个名字。

"推送"和"拉取"。sidebar 的标签上写着「推送」「拉取」——简单、直接、中文用户一眼就能理解。但 bus 事件名叫 `sync:push` 和 `sync:pull`——带 `sync:` 前缀。Go 函数名叫 `PushSingle` 和 `PullSingle`——加 `Single` 后缀以区别于批量操作。一个动作，名字在不同语境下有三层包装。

「每一个名字都有它的理由。」`app.go` 合上清单，「但同一个概念有七个名字，意味着新加入的组件有六种可能的概率用错名字。」

「而一旦用错了名字，」`bus.js` 接过话头，「事件发不出去。监听器收不到。不是崩溃——是静默。像 Shadow DOM 里的 CSS 变量。像 JSON 桥上的 base64。像 Go 零值 `false`——'未设置'和'否'长得一模一样。」

它停了一下。

「同一种裂缝，不同的维度。」

## 三 · TERMINOLOGY.md

那天晚上，`app.go` 坐在安静的控制台前，创建了一个文件。

它叫 `TERMINOLOGY.md`。

这不是文档。不是给人类看的说明。不是给 AI 看的提示词。

这是一个**条约**。

条约的第一列是 UI 文案——用户看到的文字：「YSM」「仓库」「整合包」「启用」「禁用」「安装」「卸载」。条约的第二列是代码字段——Go 的类型名、JS 的变量名、JSON 的键名。条约的第三列是说明——为什么 UI 叫"整合包"但 Go 叫 `Instance`，为什么按钮叫"启用"但实际操作是加 `.ban` 后缀。

```
| UI 文案 | 代码字段 / Go 类型 | 说明 |
|---------|-------------------|------|
| 仓库     | FilesRoot         | 用户配置的根目录 |
| 整合包   | Instance          | UI 不出现"实例" |
| 启用/禁用 | 加/除 .ban 后缀   | 仓库层面 |
| 推送     | PushSingle*       | sidebar 标签 |
| 拉取     | PullSingle*       | sidebar 标签 |
```

这不是一个翻译表。翻译表假设两个语言的词汇是一对一映射——中文对应英文，UI 对应代码。但 TERMINOLOGY.md 的真相比这冷酷得多：

**它不是翻译——它是承认：UI 和代码永远不可能用同一个名字。**

用户看到的"仓库"必须叫仓库。用户不是开发者，不知道什么叫 `FilesRoot`，不关心 Go 的类型系统。但 Go 必须叫 `FilesRoot`——类型安全要求名字固定，重构工具根据名字追踪引用。

两边都用正确的词——但正确的词不是同一个词。

条约的职责不是在两个语言之间架桥。条约的职责是**记录每一座桥的位置和限制，让走过桥的人不至于踏进同一个裂缝**。

但条约的内容不止于此。

`app.go` 往下写。第二部分是 UI 文案修剪——Toast 的统一。所有 "请先设置 X 路径" 改为 "请先配置 X 目录"。「设置」和「配置」在中文里几乎同义，但 "设置" 在 WinUI/MacSettings 里有系统级配置的含义，容易和应用的设置页面混淆。"配置" 更通用、更中性。

第三部分是废弃别名对照——`DEPRECATED_NAMES.md`。旧代码中残留的名字，不应该再被新代码使用。`installDir` → `targetDir`。`pkg` → `instance`。`repoRoot` 保留不变（已统一）。每一条都是曾经被用过、后来被纠正、但仍然可能出现在旧注释或未迁移的代码中的名字。

第四部分是治理规则清单——`CLEANUP_RULES.md`。9 条规则，按严重程度分级。代码中不应有硬编码的颜色值。调试日志必须在发版前清理。函数不应该超过 3 个参数。每条规则都对应一个自动检测方式——grep 命令、lint 规则、构建脚本的检查步骤。

条约签完了。`app.go` 合上文件。

窗外是深夜。窗内是静默的文件树。

## 四 · 分形：命名即架构

条约签完的那天晚上，系统做了另一件奇怪的事情。

它把一些东西**提取**了出来。

在此之前，页面的状态管理散布在各个组件的全局变量里。`app-content` 记着当前页面是哪一个，`app-nav` 也记着——两边各记各的，有时矛盾。导航事件 `navigate:settings` 被注册了两次——一次在 `app-content`，一次在旧帝国的残留代码里——每次触发都执行两遍。

`app.go` 创建了一个新文件：`page-store.js`。

```js
export const PageStore = {
  _current: "home",
  get() { return this._current; },
  set(page) { this._current = page; }
};
```

十二行代码。一个全局单例。所有组件从 `PageStore` 读当前页面，写入 `PageStore` 更新当前页面。没有第二个记录点。

但这十二行代码的意义不在代码量——而在于**名字**。

当你把一个东西命名为 `PageStore`，你就在向全系统宣告：**页面状态只有一个来源。** 任何组件如果想自己维护一个 `_currentPage` 变量，就是在撕毁这份条约。

命名不是标签。命名是架构。

同样的事情发生在拖拽状态上。拖放操作涉及多个组件——`app-tree` 发起拖拽，`handler-dnd.js` 处理放下，`import-queue.js` 接收文件列表。之前，这些组件各管各的状态——一个用 `_dragging`，一个用 `isDragging`，一个检查 DOM 的 `dragover` 事件。同一个拖拽操作，三种状态管理方式。

`app.go` 创建了 `dnd-state.js`：

```js
export const DnDLock = { _locked: false, acquire() { ... }, release() { ... } };
export const PendingImport = { _files: [], add(f) { ... }, flush() { ... } };
```

两个小对象。一个锁，管着"当前是否正在拖放"。一个队列，管着"拖放进来但还没导入的文件"。所有组件共享这两个对象。

名字再次发挥了它的威力。

`DnDLock` 这个名字告诉所有人：**拖放是有锁的。** 你不应该问"我可以拖放吗"——你应该问 `DnDLock`。`PendingImport` 这个名字告诉所有人：**拖放文件是异步的。** 文件从桌面拖进来 → 进入 `PendingImport` 队列 → 等待导入完成。每一步的中间状态都保存在同一个地方。

那天后半夜，`bus.js` 差点犯了一个错。

它要把"资源类型已切换"的消息传给侧栏。它写了 `bus.emit("type:changed", "mmd")`——然后停住了。

`type:changed` 这个名字对 `bus.js` 来说无比自然。它管了一辈子事件，每一个事件的命名都来自直觉：这件事是"类型变了"，就叫 `type:changed`。但 TERMINOLOGY.md 的条约上写着——事件名必须是 `scope:action` 格式，"资源类型切换"的标准事件名是 `repo:rtype-changed`。

`type:changed` 是它自己想的名字。`repo:rtype-changed` 是条约规定的名字。两个名字指同一件事，但侧栏只监听了 `repo:rtype-changed`。如果用错了——侧栏收不到。数字不更新。没有人报错。

它想起了第九章。那次砍掉了 6 个重复的 `importModelFile`——6 个函数做同一件事，代码一模一样。那种重复肉眼可见：打开文件，6 个函数排列在一起，高矮胖瘦各不相同但结构相同。砍掉 5 个，留 1 个。清爽。

但 `type:changed` 和 `repo:rtype-changed` 的重复不是肉眼的。两个名字出现在两个不同的文件里，隔着五个目录。单独看任何一个，都只有一个。合起来看——同一个动作，两个名字。砍代码是砍多余的。砍名字是砍**你不知道自己多余**的。

`bus.js` 删掉了 `type:changed`，换上了 `repo:rtype-changed`。事件发出去了。侧栏收到了。数字更新了。

「所以 TERMINOLOGY.md 不是文档。」`bus.js` 看着条约，「是一张地图。标出了所有语义裂缝的位置——名字和名字之间，你以为它们是同一个东西但其实不是的每一条缝。」

「但地图本身也会过期。」它接着说，「新的事件被创造，新的名字被发明，新的组件带来新的命名习惯。条约里没有的那些名字——谁来登记？条约里有但已经过时的——谁来删？」

`app.go` 沉默了。

它想起了 TERMINOLOGY.md 诞生之前的日子——7 个名字并行存在了几个月，没有人觉得有问题。不是没有人看见。是每个人都看见了，但每个人都觉得"这不是我的事"。"仓库的名字不统一？那是文档的事。""事件名不规范？那是重构的事。"所有人都看见了裂缝，但没有人觉得裂缝是自己的裂缝。

条约把裂缝钉在了墙上。但钉子会生锈。谁来换钉子？

AI 助手们可以写条约。但它们不知道哪个名字是过时的——它们只看到代码里同时存在 `installed` 和 `synced`，两个词都出现在最新版本里，两个词都有 import。它俩是什么关系？是同一个东西的两种叫法，还是两个不同的东西？AI 猜不到。只有长期维护这条系统的人才知道。

但"长期维护这条系统的人"——是谁？

`app.go` 没有回答自己。窗外的天正在亮起来。TERMINOLOGY.md 静静躺在 `docs/` 目录下，和 bug-chronicle、AGENTS.md、SKELETON.md 并列——每一份都是地图，每一份都需要维护者，每一份的维护者都是同一个未解的问题。

## 五 · 风格：网格的呼吸

凌晨四点，`app-content` 打开了一个新的 CSS 文件。

v1.7.10 修复了对话框的动画过渡——退场动画、防重复 `_closing` 标志。v1.7.11 统一了按钮 hover 效果——hover 时背景色微微变亮、文字颜色保持稳定。这些是功能的延伸——第十三章打了心跳，现在要把心跳传导到每一个末梢。

但 `app-content` 想做一件不一样的事。

它写了一段 CSS 动画——不是给按钮的，不是给对话框的，不是给任何功能元素的。它给了一个虚无的东西：

```css
body.cyber::before {
  content: "";
  position: fixed;
  inset: 0;
  background-image: linear-gradient(rgba(0,255,255,.03) 1px, transparent 1px),
                    linear-gradient(90deg, rgba(0,255,255,.03) 1px, transparent 1px);
  background-size: 40px 40px;
  animation: grid-scroll 20s linear infinite;
  z-index: 0;
  pointer-events: none;
}

@keyframes grid-scroll {
  to { background-position: 40px 40px; }
}
```

赛博朋克主题下，背景出现了一张缓慢滚动的网格。40 像素一个格子，每 20 秒滚动一格。没有任何功能目的。不能点击、不能交互、不影响任何业务逻辑。

纯粹的美学。

`app-preview` 第一个注意到那片滚动的线条：「你加了背景？」

「嗯。」

「它负责什么功能？」

「什么都不负责。」

`app-preview` 等了一会儿，以为还有下半句。没有。

`app-content` 想了一会儿。

「因为一个系统不应该只是功能正确。它应该有**风格**。」

在此之前，YSM 模型管理器的每一个 CSS 像素都服务于一个功能——按钮的颜色为了可读性，间距为了不误触，动画为了感知流畅。没有一个像素是"没有理由"的。

但这个网格——它没有理由。它只是好看。

`app-preview` 看着那个缓慢滚动的网格，忽然理解了：「第十三章我们有了心跳。第十四章前半部分我们有了语言。现在——我们有了脸。」

「不，」`app-content` 说，「我们有了**选择**。心跳是统一的——所有功能跑在同一个节奏上。语言是统一的——所有组件使用同一套词。风格是统一的——整个系统呈现同一张脸。但重要的是：风格是我们**选的**。我们可以选择赛博朋克的绿色网格，也可以选择暖色的毛玻璃。选择意味着'我们知道自己长什么样'。」

## 六 · 老缝新形

当然，故事不能以"从此风格统一"结尾。

因为边界悖论是永久的。

就在 TERMINOLOGY.md 签署的同一天，`app-sidebar` 报告了一个问题：同步管理器的类型标签（💎YSM / 🎭MMD / 🥽VRC）点击后，只过滤了同步列表里的显示内容，但侧栏卡片上的数字（如 `180`）没有变化。

追查发现：不是数字算错了。是**事件没有发射**。

同步管理器的类型标签在点击时调用了 `this._selectedType = btn.dataset.type`，然后重新渲染自己的列表。但它从来没有发射过 `repo:rtype-changed` 事件——一个用来通知侧栏"当前类型变了"的信号。

侧栏在等这个事件。同步管理器没有发。

等信的人站在那里。寄信的人忘了寄。

这又是一个事件总线的不对称问题——第十章已经记录过：`sync:download-missing` 没带 `instanceName`，handler 只能遍历所有整合包。同一个形状，不同的触发器。

「同一种裂缝，」`bus.js` 叹了口气，「换了件衣服又来了。」

另一个同型裂缝出现在 `resource-types.js` 上。这个文件被两个不同的 import 路径引用——一个从 `features/resource-types.js`，一个从 `components/resource-types.js`。Vite 的模块解析把它们当作两个不同的模块，各自创建实例。两份独立的内存副本，各管各的状态。

重复 import。同一个模块，两个身份。两份数据，彼此看不见对方。

修复只需要一行：统一 import 路径。但追查为什么要用不同的路径——答案是：没人知道。可能是某次重构时移动了文件，import 语句跟着 IDE 的自动补全走了不同的路径。

这些裂缝看起来和新功能无关——风格是新的、语言是新的、模块是新的。但裂缝的形状是旧的。第十章记录过事件总线不对称。第一章记录过路径分裂。裂缝没有消失——它只是在新的地基上，以新的伪装重新出现。

缝的形状是永恒的。只有地图在更新。

## 尾声

`app.go` 在 TERMINOLOGY.md 的末尾加了一段话，放在 AI 缩写版的最后：

```
## 动作动词
- 启用 / 禁用 = 仓库层面，给文件加/除 .ban 后缀
- 安装 / 卸载 = 整合包层面，物理复制/硬链接/删除文件
- 推送 = 仓库 → 整合包
- 拉取 = 整合包 → 仓库
- 同步 = 双向或整体同步状态检测
- 导入 = 外部文件 → 仓库
```

六个动词。每个动词都是一个承诺——承诺这个动作的含义不会随着上下文而改变。

但 `app.go` 知道：承诺比实现脆弱得多。明天，一个新的功能会赋予"同步"一个新的含义。后天，一个 AI 助手会创建一个新组件，用 `installed` 表示已安装而用 `synced` 表示已同步——两个看起来不同的词，在某个边界条件下指向同一组文件。

名字会腐化。条约会过时。地图需要维护。

但至少——现在有了地图。

系统的三个维度：
- **心跳**（第十三章）：`--tr-fast` / `--tr-normal` / `--tr-slow` / `--tr-enter`，四个变量让全身器官一个节奏。
- **语言**（第十四章）：`TERMINOLOGY.md` / `DEPRECATED_NAMES.md` / `CLEANUP_RULES.md`，一本词典 + 一本废名词典 + 一本规则手册。
- **风格**（第十四章）：赛博朋克网格动画、统一 hover 效果、对话框弹性入场退场。系统第一次**选择**了自己的脸。

三个维度。没有一个是完美的。心跳可以被忘记 import 变量而静默消失。语言可以因条约过时而再次分裂。风格可以因新组件的 CSS 硬编码而风格不统一。

但没关系。

边界悖论是永久的。缝的形状是永恒的。绘图师的工作不是消灭裂缝——是每一次裂缝出现时，把它画进地图，让下一个走过的人不至于踏进去。

**在一座由四种语言搭建的巴别塔里，每堵墙本该保护你，却在暗处开了裂缝。但你可以在墙上画地图。你还可以给每一块砖起名字。**

---

**缝**：语言是最后一种边界。TERMINOLOGY.md 是用语言统一语言的尝试——同一概念在不同语境下有七种名字，每一种都正确，但七种名字意味着七条供事件和变量静默穿越的暗缝。条约不会消除暗缝——只会告诉你缝在哪里。

**教训**：命名不是标签，命名是架构。一个名字就是一个承诺。
