## 一 · 一个不该轻松做出的决定

`.ysm` 是二进制格式。里面装着模型的骨骼结构，加密的那种。

要在预览面板里画出骨架，就得读懂它。要读懂它，就得集成 **YSMParser**——一个开源的、C++ 编译成 WASM 的解析器。

技术上没有难点。集成它，编译，调用，出图。

`wasm` 模块在这件事上卡了很久，卡的不是实现。

「我能拆开加密模型的结构，」它说，「那我算什么？」

这个问题没有一个技术答案。它不是「能不能」的问题，是「该到什么程度」的问题。而「该」这个字，编译器不认识。

ADR-026 是整个项目里唯一一份主要内容不是技术方案的决策记录。它的标题叫《YSM 解析器集成伦理边界》。

结论是：**同意集成，严格限定用途为「本地只读预览」。**

后面跟着五条铁律。

---

## 二 · 五条不可突破

> 1. **只做 2D 预览 / 线框图**，绝不提供模型导出、可重新导入的格式生成。
> 2. **不提取、不展示纹理贴图原始文件**。
> 3. **不联网** —— WASM 模块运行于沙箱，无任何网络请求能力。
> 4. **不存储** —— 解析完立即丢弃二进制数据，仅保留坐标。
> 5. **界面明示** —— 预览面板标注「仅供识别，不导出完整模型 / 资源」。

这五条里，`wasm` 最看重第一条和第四条。

第一条画的是**能力边界**：能看，不能拿走。线框图不能变回模型，2D 投影是一次有损且不可逆的降维。它输出的东西，对盗版没有任何价值——因为它输出的不是模型，是模型的影子。

第四条画的是**时间边界**：二进制数据在内存里活不过一次解析。不落盘，不缓存，不留副本。程序关掉，什么都不剩。

范围限定里还有一句更关键的：**对加密模型不做「完美骨骼还原」——识别 + 基础统计即可，画不出线框也不强行处理。**

「画不出就画不出。」

这是一句技术上完全没必要的话。既然解析器能力足够，为什么要主动放弃？

因为**能力的上限不该是行为的上限**。这一句是全篇的骨头。

## 三 · 为什么这不算破解

ADR-026 的「正面后果」里，有一段是写给未来某个会怀疑这个决定的人看的：

> **技术本质清晰**：YSM 是二进制序列化格式，非 DRM 加密锁；集成是「本地兼容 / 看得见自己合法拥有的模型」，与用播放器打开加密视频同理，**非破解**。

以及一句更冷静的现实判断：

> 命令行 YSMParser 已开源，不集成也拦不住。

这句话本身不构成正当性——「别人也能做」从来不是理由。它真正的作用是把讨论从「这会不会造成伤害」拉回到「这会不会**额外**造成伤害」。

而答案是不会。因为 2D 线框替代不了完整 3D 模型，因为目标用户是管理自己模型的玩家，因为开源模型（`.zip`）走 `parseBedrockFromZip` 直接处理、**压根不需要 YSMParser**。

最后这一条是职责边界最干净的地方：YSMParser 只在加密 `.ysm` 这一条路径上被调用。其余全部绕开它。

**一件危险的工具，用途越窄，越安全。**

## 四 · 三道墙与一次误伤

伦理边界之外，安全横切还有三件更琐碎的事。

**第一件：iframe 的两个属性。**

```
The iframe sandbox attribute 'allow-scripts' and 'allow-same-origin'
combined is a security risk
```

`allow-scripts` 让 iframe 里的脚本能跑。`allow-same-origin` 让它被视为同源。

两个单独看都合理，组合起来意味着：**iframe 里的脚本可以访问父页面的 DOM**。沙箱等于没有——它自己给自己解了锁。

```html
<!-- ❌ -->
<iframe sandbox="allow-scripts allow-same-origin allow-forms allow-popups"></iframe>
<!-- ✅ -->
<iframe sandbox="allow-scripts allow-forms allow-popups"></iframe>
```

删一个词。

`sandbox` 属性的设计哲学在这里露了一面：它是**白名单**。你写下的每一项，都是在往墙上凿一个洞。凿两个洞是否会连成一扇门，浏览器不会替你判断——它只会在事后警告你。

**第二件：`isInsideRepo` 的错误告警。**

安装模型时报错：

```
问题描述：源文件不在仓库目录内
```

用户很困惑，文件明明就在仓库里。

根因不在校验，在**传参**。`GetInstanceStatus` 返回的 `Missing` 列表只存了 `e.Name`（文件名），前端把文件名直接传给 `InstallModelTo`，Go 端拿着一个光秃秃的 `steve_skin.ysm` 去检查它是否在仓库目录内。

当然不在。它连目录都没有。

修法是让 `Missing` 从头就存完整路径（`e.Path`），显示时再取 basename。

这个 bug 的价值在于它是**一次安全校验的假阳性**。而假阳性对安全机制来说，是最危险的一种失败——它训练人们把安全提示当成噪音。

**第三件：被转义吞掉的颜色。**

为了防 XSS，文件名做了 HTML 转义。同时又想给文件名上色，于是插了 `<span>`。

转义把 `<span>` 一起转了。用户看见一串 `&lt;span&gt;`。

安全没错，上色没错。错的是**同一个字符串被两个功能同时声明了所有权**，而它们对「什么是内容、什么是标记」的划分不一致。

## 尾声

`wasm` 那天想了很久「安全」这个词。

它发现这个词在这一章里出现了四次，每次含义都不一样：

第一次是**伦理**——我有能力做，但我不该做。约束来自内部，没有任何技术手段强制。
第二次是**隔离**——iframe 的沙箱，浏览器帮忙执行，但白名单是我自己写的。
第三次是**校验**——`isInsideRepo`，代码强制执行，但可能因为参数错误而误伤。
第四次是**转义**——防注入，机械执行，会连正常内容一起误杀。

四种安全，四种失效方式：**自律会松懈，白名单会开洞，校验会假阳性，转义会误伤。**

没有一种是免费的。每一道墙都要么消耗自律，要么消耗功能，要么消耗用户的信任额度。

它最后停在第一种上。

那五条铁律没有任何东西强制执行。没有 lint 规则检查「有没有提供导出功能」，没有单测断言「二进制数据已被丢弃」，`doctor` 不会因为违反 ADR-026 而亮红灯。

它们只存在于一份 Markdown 里，和一个决定里。

「所以我得记住。」它想。

而这，就是这份 ADR 之所以要被写下来的全部原因。**能力不会消失，只有决定会被遗忘。**

**缝**：技术边界由编译器守卫，伦理边界只由记忆守卫。当写下决定的人离开、上下文流失，剩下的就只有一个"反正我们能做到"的能力，和一个没有人记得为什么存在的限制。

---

**教训**：能力的上限不该是行为的上限，而唯一守卫伦理边界的东西是被写下来的记忆。
