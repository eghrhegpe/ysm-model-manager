# 诊断页「同语义多处实现」收敛清单（只读审计）

> 范围：`frontend/src/views/app-content/diagnostics/**`（19 个生产 .ts，约 3,700 行）。Go 侧仅只读参照，不做评价。
> 判据纪律：**真同语义 = 输入/输出契约可逐字互换且互换后行为不变（含错误分支、空值、顺序）**。契约不同者一律降级为「同用途不同口径」或列入必要差异。
> 反向前提（已核实，故本清单很短）：本页的共享层基本被遵守——`createLoadGuard()` 6 个模块全覆盖（logs / perf-single / perf-concurrent / perf-gui-flow / perf-scan-bench / perf-log）、`EscFn` 单点托管于 `logs.ts:13` 并被全页 import、`sectionHeader / setBusy / getOutBox / respHasOutput` 由 `perf-common.ts` 统一出口、`UI_ICONS` 无一处 emoji 硬编码图标、`formatBytes` 在 health / perf-matrix 均已委托、`perfOrderOptionsHTML()`（tpl.ts:136）被 single / conc 共用、`parsePerfTargetValue / readPerfOrder / populatePerfTargetOptions / perfTargetEchoHTML` 被 single / conc 共用。**下面的清单是扣掉这些之后剩下的债。**

## 一、摘要（最高价值 5 条）

1. **web 门禁同一段 8 行样板被抄了 5 份**（3 份逐字相同、2 份只差 i18n 键）：`perf-concurrent.ts:134-142`、`perf-gui-flow.ts:39-47`、`perf-scan-bench.ts:240-248`、`conflicts.ts:37-45`、`conflicts.ts:191-199`；5 个调用点（:300 / :134 / :256 / :159 / :266）。可收成一个 `webGate(key)`，**零行为变化**。
2. **`perf-concurrent.ts:315-321` 手写错误横幅，正绕过同目录已导出的 `errorHTML`**（`perf-common.ts:113-115`），展开后字符串逐字相同；同场景的 `perf-scan-bench.ts:278` 走的是 `errorHTML` —— 同一页两种写法。
3. **`perf-common.ts:100-102` 的 `setErrorMsg` 与 `:113-115` 的 `errorHTML` 是同一字符串的两份实现**（一个赋值一个 return），7 个 `setErrorMsg` 调用点 + 4 个 `errorHTML` 调用点因此各自维护同一段字面量。
4. **「命令成功但载荷形状不对 / 命令失败」失败分支在 5 个模块同形各写一遍**（`perf-single-bench.ts:540-546`、`perf-concurrent.ts:307-312`、`perf-scan-bench.ts:268-273`、`perf-gui-flow.ts:143-152`、`perf-log.ts:79-85`），唯一差异是上屏文案键。
5. **`utils/dom/clipboard.ts|copyText` 这个全仓既有单点被本页绕开**：`perf-common.ts:29-53` 自建第二份（textarea 降级块 `perf-common.ts:39-44` 与 `clipboard.ts:28-33` 逐字相同，`init.ts:21-26` 是第三份），`init.ts:20-30 / 91-115 / 117-137` 是第三、四份（内含一处「execCommand 也失败仍报已复制」的诚实缺陷）。
