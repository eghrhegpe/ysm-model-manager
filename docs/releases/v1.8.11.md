# v1.8.11 — 加载路径大统一 + 作者头像修复

**发布日期：** 2026-06-17

---

## 🏗 架构重构：模型加载路径统一

**之前**：4 条独立加载路径（`preview-loader.js:loadModelData`、`preview-skeleton.js:loadModel2D`、`index.js:_loadModel2D`、`_loadPreviewImage`），各维护自己的 cache→WASM→Go 三阶段。

**之后**：统一为 `preview-skeleton.js → loadModelData` 单一路径。

| 动作 | 文件 |
|------|------|
| 删除死代码 `_loadModel2D`（index.js，~320 行从未被调用） | `index.js` |
| `preview-skeleton.js:loadModel2D` 删除自建加载段，委托 `loadModelData` | `preview-skeleton.js` |
| `isYsm` 修正为 `/\.ysm$/i`（去掉 `.json`，JSON 不走 WASM） | `preview-loader.js` |
| Go 路径 badge 统一为 `📦 Go 原生解析`（不再区分 CLI） | `preview-loader.js` |

## 🐛 Bug 修复

| Bug | 根因 | 修复 |
|-----|------|------|
| `.json` 解压目录作者头像不显示 | `parseYsmJsonDirect` 写死 `avatarUrl: null` | WASM 解码时用 `ReadFileBytes` 从 `avatar/` 目录加载 |
| `.json` 作者列表不出现 | `preview-skeleton.js` 自建加载流，不从缓存补 authors | 统一走 `loadModelData`，post-load 从缓存补充 |
| 加密 `.ysm` 作者全丢 | `const ysmAuthors` 遮蔽外层 `let` | 删内层声明 |
| WASM 缓存误拦截重试 | 空骨骼 `geometry` 也视为缓存命中（`cached?.geometry`） | 改为 `cached?.geometry?.bones?.length` |
| WASM 对 `.json` 也初始化 | WASM init 在文件类型判断之前 | `.json` 分支提到 WASM init 之前 |
| WASM 重复解码（两次） | `_loadPreviewImage` 和 `loadModelData` 各调一次 | `_wasmFailed` 缓存标记秒回 |
| MEMFS 引用 `bytes` 越界 | 重构后 `bytes` 出 try 作用域 | 提到函数级 |
| 头像文件路径双倍 | `baseDir + "/avatar/" + "avatar/wmdj.jpg"` | 判断是否已有 `avatar/` 前缀 |
| WASM 解码失败却仍尝试 CLI | `processModelFile` 仅处理 `models/` 前缀 | 无 `ysm.json` 时主动回退 Go 处理 |

## ✨ 新功能

- **Go 绑定 `CacheModelAvatars`** — 预览 `.json` 模型时异步将头像持久化到 `creators_cache/`，供创作者界面使用（`app_avatar.go`）
- **旧格式包兼容** — 无 `ysm.json` 的 `.ysm` 包自动回退 Go（Go 有文件名启发式纹理匹配，避免 WASM 全塞 `texIdx=0`）

## 🎨 UI 改进

- `📎 纹理分配` 改为 `📎 含 N 张额外纹理（共 M 张）` — 用户友好格式（`tpl.js`）

## 🔧 技术债务

- `decodeYsmViaWasm` 减少一次 WASM 模块加载（缓存 `_wasmFailed`）
