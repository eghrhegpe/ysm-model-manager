# 大模块审核子代理流水线 Playbook

> 适用范围：单模块 / 跨模块大范围代码审核，尤其是「主模型上下文有限、需要并行发散审查」的场景。
> 设计约束：本流水线专门消化「子代理与主模型思维链不互通」这一事实——子代理的推理过程对主模型不可见，主模型只能看到子代理返回的结构化报告。

> **工具优先级原则（2026-08-05 实证）**：终端有现成工具时，优先用终端工具，不派子代理。
> - 提交/文件级审核 → 用 `code_review` 工具（内置审核器，diff 级精确，成本中）——2026-08-05 实测对文档/改名/生成物工作有效：2 次调用抓 2 个 P2（AGENTS.md 口令漏改）
> - 大范围并行发散（多模块、主模型上下文不足）→ 才走本流水线（GLM-5.2 一轮 + 主模型复核，成本高）
> - 轻量模块（<500 行）或文档/生成物类工作 → 主模型直审比流水线更经济（§7.1 实证）
> 判断顺序：**终端工具 > 主模型直审 > 子代理流水线**。

---

## 1. 核心约束：思维链不互通

子代理（Agent 工具派生的 general-purpose 子进程）拥有**独立上下文**，其推理链（chain-of-thought）在返回后**对主模型不可见**。主模型最终只拿到子代理的「最终回复」，拿不到它中间的思考步骤。

由此产生两类风险：

- **风险 A（误信）**：子代理可能产出「看似合理但未经源码核实」的结论，主模型若照单全收，会把错误当事实。
- **风险 B（失焦）**：自由发散的子代理会产出大量低相关意见，淹没真问题。

对策（贯穿全流水线）：

1. **限定上下文**：只把 `source_files` + 知识卡 + 显式 rubric 喂给子代理，禁止把主模型自己的分析当上下文传入（否则既污染独立性，又没意义）。
2. **结构化输出契约**：强制子代理按固定格式返回（见 §4），主模型无需读其思维链即可逐字段核对。
3. **主模型独立 verify**：对 P1/P2 结论，主模型必须自己读源码复核，不依赖子代理的推理。
4. **共享真相源**：子代理与主模型都锚定「当前源码」+ 知识卡，而非锚定彼此的想法。

## 2. 流水线（4 阶段）

### Phase 0 — 知识库健康度诊断（主模型执行）
目的：确认知识库可信，才敢拿它做扇出索引。

```bash
node scripts/doctor.mjs --docs            # 轻量秒级：链接/漂移/ADR 登记
node scripts/check-knowledge-drift.mjs   # 知识卡漂移
node scripts/check-doc-drift.mjs --json  # 文档三一致
```

通过标准：三项均 `[OK]`，`git status` clean。若漂移，先修知识库再进入 Phase 1。

### Phase 1 — 固化发散种子（主模型执行）
目的：用项目真实反模式给子代理当锚，避免自由发散。

```bash
node scripts/ai-mistake-tracker.ts --limit 12 --json  # 高频犯错区 / 文件热力图
node scripts/check-redlines.ts --audit               # 12 红线 + B 类盘问锚点
rg --line-number '^(export )?(async )?(function|const|class) ' frontend/src  # 符号级 file:line 导航（funcmap 已拆除，rg 取代）
```

把 `ai-mistake-tracker` 的「反模式分类」与「文件热点」作为子代理 prompt 的优先关注项。

### Phase 2 — 以知识卡为单元扇出（主模型派发子代理）
用 `docs/knowledge/index.md` 枢纽索引按模块切分，**每个知识卡 = 一个扇出单元**。子代理 prompt 见 §4。

- 子代理**只读**，不改文件、不跑构建。
- 并行派发多个子代理，各自独立、互不共享上下文。

### Phase 3 — 聚合对账（主模型收口）
1. 子代理报告按固定格式回填：总体结论 → 亮点 → 风险表 P1–P4 → 类型安全 → 数据流追踪 → 知识卡漂移。
2. 主模型**去重**（同缺陷多代理重复报）、**抽样 verify**（对 P1/P2 读源码独立确认）。
3. 汇总成统一审核报告（格式参考 `docs/review/validation-import-queue.md`）。

---

## 3. 审核 rubric（喂给子代理的标准）

**5 维度**：类型安全（undefined/null 守卫、JSDoc、无隐式全局） / 资源管理（事件订阅配对、`bus.on`→`_unsubs`、`addEventListener` 配对） / 测试覆盖 / 功能正确性（并发守护、undefined 守卫、Promise 不丢弃、finally 必走） / 设计质量（状态来源唯一、副作用可追踪、并发安全、错误边界、资源释放链路、UI 文案规范）。

**4 思维模型**：数据流追踪（状态从哪来/谁改/流到哪，审计所有写入点，标注幽灵路径） / 生命周期完整性（订阅与清理是否同抽象层配对） / 并发与边界（快速连点、异步过期标记、竞态） / 异常契约（catch 后状态一致、finally 覆盖、Promise 不静默吞错）。

## 4. 子代理 prompt 模板（bounded + structured）

```
你执行单模块只读代码审查，禁止改文件、禁止跑构建。上下文与主模型隔离，只接收本 prompt 内容。

TARGET（完整读取）：
- <source_files 来自知识卡>

SHARED GROUND TRUTH（读取知识卡；以源码为终极真相，冲突只报告不盲信）：
- docs/knowledge/<card>.md

REVIEW RUBRIC：<粘贴 §3 的 5 维度 + 4 思维模型>

PROJECT ANTI-PATTERNS（优先关注，来自 ai-mistake-tracker）：
- <粘贴 Phase 1 取到的反模式分类与文件热点>

OUTPUT FORMAT（仅返回结构化报告，不披露工具链）：
1. 总体结论：(通过/有条件通过/不通过) + 一句话理由
2. 亮点：(bullet)
3. 风险表：等级(P1-P4) | 位置 file:line | 现象 | 处置建议
4. 类型安全：结论 + 关键发现
5. 数据流追踪：列出关键状态的所有写入方，标注幽灵路径
6. 知识卡漂移：是/否 + 具体不符点
务必给 file:line，禁止编造行号。
```

---

## 5. 主模型对账协议（verify）

- 对子代理报告的每个 **P1/P2**，主模型必须亲自 `Read`/`Grep` 源码确认，不读子代理思维链。
- verify 分两层：
  - **事实层**：「现象是否真实存在」「位置是否准确」——`Grep`/`Read` 源码直接确认。
  - **价值层**：「这算不算缺陷」——核实组件/API 自身的契约（如组件是否设计了 dispose 方法却被调用方丢弃；模块是否有充分消费锚点；catch 静默是否是设计取舍）。**现象存在 ≠ 需要修**，判断层必须主模型自己做。
- 发现子代理误报：在汇总报告中标注「主模型复核未证实」并说明原因。
- 发现「现象证实但价值性存疑」（如 catch 静默是设计取舍、占位 handler 是未落地功能）：标注「撤修」并说明理由，不强行改。
- 发现知识卡漂移：同步修知识卡（消除漂移，不静默假定卡片正确）。

---

## 6. 风险与权衡

| 项 | 说明 | 缓解 |
|---|---|---|
| 子代理误报 | 隔离上下文下可能产出未经核实结论 | Phase 3 独立 verify |
| 发散失焦 | 自由发散产噪音 | Phase 1 反模式锚定 |
| 子代理上下文溢出 | 给整仓会淹没信号 | 只给 `source_files` + 知识卡 |
| 聚合偏见 | 主模型只看摘要漏真问题 | P1/P2 全量 verify，不抽样跳过 |
| 审查期并发改炸 | 多代理同时改同一模块 | 子代理只读；真正改代码另起一轮按特性 scope 提交 |

## 7. 验证先例

见 `docs/review/validation-import-queue.md`：`import-queue.ts` 实跑本流水线，子代理 4 项高影响结论经主模型独立读源码**全部证实**，证明「思维链不互通」被结构化输出 + 独立 verify 消化，而非放大。

### 7.1 主模型直审先例（2026-08-05，16 模块按功能审核）

见 `docs/review-report.md` 审计单元 6：本轮未走子代理流水线（主模型上下文充足，逐模块串行直审），16 模块经 §3 rubric + §4 思维模型盘问，印证两点：

- **价值性复核（§5 价值层）确为必需**：本轮 13 处隐患中 5 处「现象证实但价值性存疑」撤修——`import-queue.ts` async IIFE 静默 catch（预览临时文件写入失败不该打断表单流程）、`context-menus.ts` 占位 handler（未落地功能）、`rename.ts` async handler 无 await（纯同步）、`tag-editor.ts` save 无 finally（无 disabled 卡死风险）、`app-preview` 静默 catch（头像缓存/剪贴板非用户交互路径）。**若照单全收会引入 5 处过度修复**。
- **rubric + 思维模型不依赖子代理隔离也能用**：主模型直审走同一套 5 维度 + 4 思维模型，产出同结构报告；流水线的子代理隔离仅在「主模型上下文不足、需并行发散」时必要——轻量模块（<500 行）或主模型上下文充足时，直审比流水线更经济（省 Phase 0/1/2 派发开销）。

**两族隐患规律**（反哺 Phase 1 反模式锚）：
- 前端「异步失败静默」11 处 — 陷阱 #3「按钮异步后卡死」变体（Promise 链无 `.catch` / async handler 无 try/catch / 前置 await 在 try 外 / 按钮 disabled 无 finally 恢复 / `model:select` 无代际守卫）
- 后端「半截文件残留」2 处 — 陷阱 #8 衍生（`io.Copy` 失败未清目标 / `os.Symlink` 错误未检查）

下次 Phase 1 取反模式锚时，把这两族作为优先关注项喂给子代理。
